# TagBack Windows 키오스크

TagBack Windows 키오스크는 NFC 리더기가 연결된 현장에서 공용물품의 대여와 반납을 처리하는 설치형 앱입니다.

사용자는 키오스크에서 이용자를 확인하고 NFC 태그를 인식한 뒤 대여 또는 반납을 확정합니다. 관리자는 키오스크 관리자 모드에서 물품에 NFC 태그를 연결하거나 교체할 수 있습니다.

Windows 키오스크는 공통 키오스크 화면을 Electron 앱에 포함하고, Java PC/SC를 통해 NFC 리더기와 연결합니다.

---

## 주요 기능

### 대여·반납

- 이용 코드를 통한 이용자 확인
- NFC 태그를 통한 물품 식별
- 대여·반납 내용 확인 및 서버 저장
- 반납 물품의 정상·손상 상태 확인
- 처리 결과가 불명확한 거래의 확인과 복구

### 관리자 기능

- 공통 관리자 비밀번호를 통한 관리자 모드 로그인
- 태그 등록 대기 물품 조회
- NFC 태그 연결 및 교체
- 관리자 웹 열기
- 키오스크 설정 잠금 해제

### 장치 및 운영 기능

- 서버 연결과 인증서 상태 확인
- 연결된 NFC 리더기 탐색 및 재연결
- 리더기 서명 키의 암호화 저장
- 비밀값을 제외한 진단 정보 내보내기
- 선택형 Windows 로그인 시 자동 실행
- 암호화된 거래 복구 기록 저장

---

## 실행 준비 사항

키오스크를 사용하기 전에 다음 항목을 준비합니다.

- Windows x64 실행 환경
- 실행 중인 TagBack 서버
- 연결할 서버의 HTTPS 주소
- NFC 리더기
- 서버 관리자에게 제공받은 리더기 ID와 서명 키
- 관리자 기능을 사용할 공통 관리자 비밀번호

자체 서명 인증서를 사용하는 서버에 연결할 때는 인증서 파일과 관리자가 제공한 SHA-256 지문도 준비합니다.

서버나 리더기가 설정되지 않은 상태에서는 연결되지 않았다는 안내가 표시되며, 이용을 시작할 수 없습니다.

---

## 설치와 실행

Windows 키오스크 설치 파일은 빌드 후 다음 경로에서 확인할 수 있습니다.

```text
kiosk/windows/out/make/squirrel.windows/x64/
```

0.1.4 시험 설치 파일:

```text
TagBackKiosk-0.1.4-trial-Setup.exe
```

설치 전 실행 중인 거래가 없는지 확인하고 기존 앱을 종료합니다. 이후 설치 파일을 실행해 안내에 따라 설치합니다.

직접 실행용 앱은 다음 경로에 생성됩니다.

```text
kiosk/windows/out/TagBackKiosk-win32-x64/TagBackKiosk.exe
```

직접 실행용 앱을 다른 위치로 옮길 때는 실행 파일만 복사하지 말고 같은 폴더 전체를 함께 옮겨야 합니다.

> 0.1.4 설치 파일은 코드 서명되지 않은 시험판입니다. 다른 PC 설치와 실물 NFC 업무 검증은 별도로 필요합니다.

## 초기 설정

앱을 처음 실행하면 설정 화면이 열립니다.

다음 정보를 입력하거나 확인합니다.

1. 서버 HTTPS 주소
2. 리더기 ID
3. 필요한 경우 리더기 이름 필터
4. 서버 관리자가 제공한 리더기 서명 키
5. 서버 인증서 신뢰 설정

설정 후 서버와 리더기 연결 상태를 확인합니다.

서명 키는 설정 화면을 통해 입력합니다. 키를 설정 파일, 문서, 명령 인자 또는 환경변수에 직접 기록하지 않습니다.

서버를 변경할 때는 해당 서버에서 사용하는 리더기 ID와 서명 키도 함께 확인해야 합니다.

## 연결·설정 화면

시작 화면의 **연결·설정** 또는 `Ctrl+Shift+S`로 설정 화면을 열 수 있습니다.

설정 화면에서 다음 항목을 확인할 수 있습니다.

- 서버 응답 상태
- 서버 인증서 상태
- NFC 리더기 연결 상태
- 리더기 키 저장 상태

다음 기능도 제공합니다.

- 연결된 리더기 찾기
- 리더기 다시 연결
- 관리자 웹 열기
- 진단 정보 저장

진단 정보에는 비밀번호나 서명 키 같은 비밀값을 포함하지 않습니다.

### 설정 잠금

이미 설정된 기기의 설정을 변경하려면 공통 관리자 비밀번호로 잠금을 해제합니다. 잠금 해제는 5분 동안 유지됩니다.

처음 설정하는 기기는 Windows 운영자가 설정합니다.

서버 장애로 관리자 인증을 할 수 없는 경우에는 앱을 종료한 뒤 운영자가 다음 옵션으로 설정 화면을 열 수 있습니다.

```powershell
TagBackKiosk.exe --configure
```

이 기능은 Windows 운영자를 위한 복구 경로입니다. 키오스크 PC의 Windows 계정 접근 권한을 적절하게 관리해야 합니다.

---

## 서버 인증서

키오스크는 HTTPS 서버에 연결합니다.

기본적으로 Windows 시스템 인증서를 포함한 신뢰 저장소를 사용합니다. 자체 서명 인증서를 사용하는 서버는 설정 화면에서 `.crt` 또는 `.pem` 인증서를 선택하고, 관리자가 제공한 SHA-256 지문과 일치하는지 확인합니다.

추가한 인증서 신뢰는 설정한 HTTPS origin에 한정됩니다. 호스트명과 인증서 유효기간도 검증합니다.

서버 인증서를 신뢰하기 위해 Windows 전체의 인증서 검증이나 TLS 검증을 해제하지 않습니다.

---

## 관리자 모드와 태그 등록

관리자는 사용자 인증과 분리된 공통 관리자 비밀번호로 키오스크 관리자 모드에 로그인합니다.

### 신규 물품에 태그 연결

1. 관리자 웹에서 물품을 등록합니다.
2. 물품이 태그 등록 대기 상태로 저장되었는지 확인합니다.
3. 키오스크 시작 화면에서 **관리자 태그 등록**을 선택합니다.
4. 공통 관리자 비밀번호로 로그인합니다.
5. 태그를 연결할 물품을 선택합니다.
6. NFC 태그를 리더기에 인식시킵니다.
7. 물품과 태그 정보를 확인하고 연결을 확정합니다.
8. 작업을 마친 뒤 관리자 모드를 종료합니다.

### 기존 태그 교체

관리자 모드에서 물품을 검색하고 새 태그를 인식해 교체합니다.

- 대여 중인 물품의 태그는 교체할 수 없습니다.
- 점검·수리 상태의 물품은 태그를 교체해도 기존 상태를 유지합니다.
- 이미 사용 중인 UID나 재사용된 스캔은 거부됩니다.

---

## 대여·반납

키오스크는 이용자 확인과 물품 인식을 거쳐 대여·반납을 처리합니다.

1. 시작 화면에서 대여 또는 반납을 선택합니다.
2. 화면 안내에 따라 이용자와 물품을 확인합니다.
3. NFC 태그를 리더기에 인식시킵니다.
4. 대여 또는 반납 내용을 확인합니다.
5. 필요한 경우 반납 물품의 상태를 선택합니다.
6. 최종 확인 후 서버 저장이 성공하면 결과를 표시합니다.

NFC 태그를 인식한 것만으로 대여나 반납이 확정되지는 않습니다.

---

## 거래 복구

키오스크는 대여·반납·태그 변경 요청을 서버에 보내기 전에 거래 복구 기록을 저장합니다.

- 복구 기록은 Windows 사용자 계정에 연결된 DPAPI로 암호화합니다.
- 로컬 복구 기록을 저장하지 못하면 서버에 쓰기 요청을 보내지 않습니다.
- 응답이 유실되거나 앱이 종료되면, 재시작 후 같은 작업을 기준으로 결과를 확인합니다.
- 복구 기록을 해독할 수 없으면 기록을 임의로 삭제하지 않고 거래를 차단합니다.

### 자동으로 결과를 확인할 수 없는 경우

대여 토큰 만료 등으로 서버가 거래 결과를 자동 확인하지 못할 수 있습니다.

이 경우 관리자는 다음 절차를 따릅니다.

1. 관리자 웹의 거래 기록을 확인합니다.
2. 실제 물품 상태와 기록을 대조합니다.
3. 관리자 비밀번호로 다시 인증합니다.
4. 확인 내용을 입력하고 명시적으로 확인합니다.
5. 기기의 거래 제한을 해제합니다.

이 절차는 기기의 운영 제한을 해제하며, 서버의 거래 기록을 임의로 변경하지 않습니다.

확인 내용을 작성할 때 비밀번호나 개인정보를 입력하지 않습니다.

## 프로필과 설정 보관

기본 프로필은 다음 경로에 저장됩니다.

```text
%APPDATA%\TagBackKiosk
```

테스트 시에는 별도 프로필을 지정할 수 있습니다.

```powershell
TagBackKiosk.exe --kiosk-profile=C:\TagBackTrial
```

설정과 암호화된 키는 해당 프로필과 Windows 사용자 계정에 연결됩니다. 키를 다른 Windows 계정이나 다른 PC에 복사해 그대로 재사용할 수 있다고 가정하지 않습니다.

설정을 백업할 때는 필요한 암호화 키와 관련 상태 파일을 함께 보관하고, 접근 권한을 제한합니다.

## 자동 실행

Windows 로그인 시 키오스크 앱을 자동 실행하도록 선택할 수 있습니다.

- 자동 실행은 기본적으로 꺼져 있습니다.
- 설정 화면에서 필요에 따라 켜거나 끌 수 있습니다.
- 별도 시험 프로필에서는 자동 실행을 설정하지 않습니다.
- 자동 업데이트는 제공하지 않습니다.

## Windows 앱 빌드

### 빌드 환경

- Windows x64
- Node.js 24
- npm
- pnpm
- JDK 21
- `java`와 `jlink` 실행 경로 설정
- Gradle 의존성 준비

실행 PC에는 앱에 포함된 런타임을 사용하므로 Node.js와 Java를 별도로 설치할 필요가 없습니다.

### 빌드와 테스트

저장소 루트에서 실행합니다.

```powershell
cd kiosk/windows

npm ci
npm test
npm run make
npm run test:smoke
```

`npm run make`는 공통 키오스크 UI, Java 리더기 브리지, Java 런타임과 Windows 앱을 묶어 설치 파일을 생성합니다.

`resources/`는 빌드 과정에서 생성되는 폴더입니다. 이 폴더에 실제 서버 설정이나 서명 키를 넣지 않습니다.

### 추가 검증

Windows 키오스크 폴더에서 업그레이드 시험을 실행할 수 있습니다.

```powershell
node scripts/upgrade-smoke.cjs
```

프론트엔드 키오스크 호스트 테스트는 `frontend/`에서 실행합니다.

```powershell
pnpm test:kiosk-host
```

패키지 시험은 별도 시험 프로필과 로컬 HTTPS fixture를 사용합니다. 실제 운영 DB나 실물 NFC 장치의 검증을 대신하지 않습니다.

## 검증 범위와 제한

Windows 키오스크 0.1.4 통합본은 빌드와 단위 테스트, 시험 환경의 패키지 실행 및 거래 복구 관련 검증 기록이 있습니다.

다음 항목은 별도 검증이 필요합니다.

- 실물 NFC 태그 등록·교체
- 실물 NFC 리더기를 이용한 대여·반납
- 다른 PC에서의 설치 및 운영 확인
- 실제 Windows 로그인 시 자동 실행 확인
- 운영 DB를 사용하는 전체 업무 흐름
- 코드 서명 및 배포 환경 검증

Android 구현은 별도 범위이며 현재 보류 중입니다.
