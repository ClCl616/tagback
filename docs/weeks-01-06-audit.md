# 노션 1~6주차 반영 점검

> 과거 점검 기록: 아래는 2026-10-06 당시 작업 폴더의 결과다. 현재 미완료 목록으로 사용하지 않는다. 이후 병합된 성과와 남은 작업은 [현재 구현·검증 현황](project-status.md)을 참고한다.

점검일: 2026-10-06. 대상: 현재 작업 폴더 `feat/mobile-auth-catalog`, HEAD `66566de`와 커밋되지 않은 변경 포함.

## 결론과 범위

**1~6주차 전체 완료 상태는 아니다.** 기획·조사 자료와 사용자 모바일/키오스크의 모의 흐름은 상당 부분 반영됐다. 실제 서버 인증·권한·물품 API, 관리자 UI, NFC 실장비 연결, 태그 등록·교체는 남아 있다. 6주차 일정은 10월 6~12일이므로 현재 미완료를 일정 지연이라고 단정하지 않는다.

노션의 주차별 페이지 1~6, 프로젝트 허브, 담당자별 이전 활동과 결과물 페이지를 브라우저로 읽고 현재 소스·DB 마이그레이션·테스트와 대조했다. 노션 체크 여부만으로 완료를 판정하지 않았다. 다른 팀원의 PC·미통합 브랜치·운영 서버는 이번 확인 범위가 아니다. 원격 최신 변경을 가져오거나 브랜치를 전환하지 않았다.

- **반영**: 문서/화면/코드가 해당 요구를 충족한다. 실제 연결 여부는 별도로 표시한다.
- **부분 반영**: 모의 구현이나 설계만 있고 실제 연동/운영 단계가 남았다.
- **미반영**: 현재 코드에서 필요한 기능을 찾을 수 없다.
- **확인 필요**: 실행·하드웨어·팀 승인 등 근거가 부족하다.
- **정책 변경**: 이후 사용자 지시와 확정 기록을 우선한다. 예전 요구를 복원할 누락으로 취급하지 않는다.

## 중요한 구현 차이

1. **API라는 이름의 모의 구현**: `frontend/src/shared/api.ts`의 ServiceApi는 브라우저 localStorage/Web Locks를 사용한다. `auth.ts`도 모의 DB를 공유한다. 서버 HTTP 연결·여러 실제 기기 동기화·운영 보안을 입증하지 않는다.
2. **회원 스키마 부족**: users에는 phone_number/password_hash/role 등이 있지만 이름·직업, PIN 실패/잠금, SMS proof 소비, 세션/브라우저 등록 폐기 상태가 없다. 최신 가입/인증 정책을 백엔드에 구현하려면 새 마이그레이션과 처리 로직이 필요하다.
3. **태그 교체 설계와 DB 충돌**: V4는 물품당 태그 행 1개만 허용한다. 비활성 이전 태그를 남기면서 새 활성 태그를 연결하는 노션 설계를 지원하려면 상태/이력 구조와 활성 태그 유일성 규칙을 다시 정해야 한다.
4. **상태 계약 차이**: frontend ItemStatus는 available/rented/inspection, DB는 AVAILABLE/RENTED/INSPECTION/REPAIR다. 수리 상태 표시·관리와 서버 응답 변환 계약이 필요하다. 관리자 점검 완료→가용 재고 복귀도 없다.
5. **실물 NFC 미연결**: `shared/nfc.ts`는 BroadcastChannel 수신이다. `nfc/reader-bridge`에는 실행 코드가 없고 테스트 계획의 결과 기록도 비어 있다.
6. **문서 최신화 필요**: `docs/decisions.md` 상단 합의 필요 항목 중 로그인 방식은 하단 최신 확정과 겹친다. `docs/mobile-auth-catalog.md`에는 예전 password 가입 계약이 남아 있다. 노션과 저장소 문서의 최신 정책을 한 기준으로 맞출 필요가 있다.

## 누락으로 계산하면 안 되는 후속 변경

| 초기 문서 | 현재 우선하는 요구 |
|---|---|
| 학번/비밀번호 | 전화번호·6자리 PIN, 가입/복구/번호 변경의 SMS |
| 새 브라우저 로그인에도 SMS | 사용자 후속 지시: 전화번호→PIN |
| 회원가입 전화번호부터 | 이름·직업 Select→전화번호→SMS→PIN |
| 스마트폰 NFC로 직접 처리 | 현재 키오스크/USB 리더기 방향. 모바일은 조회·인증·대여 코드 제공 |
| 예약 포함 시나리오 | 현재 사용자 UI 범위에서 예약 제외(`docs/service-ui.md`) |
| 여러 대여소 및 대여소 테이블 | 현재 1곳, 선택 UI/stationId 유지. DB ID 매핑은 합의 필요 |
| 브라우저 등록 해제 버튼 | 사용자 지시로 화면에서 제거. 내부 정책/adapter 존재와 구분 |
| 로그인 후 next 복귀 | 로그인 성공은 메인 `/mobile` 이동 |
| 수동 새 대여 코드 확인 | 3분 유효, 코드 화면에서 만료/사용 시 자동 갱신 |

관리자 UI·실 API·실 NFC는 이전 사용자 UI 작업에서 후속 범위로 명시되었다. 따라서 이전 화면 작업의 결함으로 단정하지 않지만, **노션 1~6주차 전체 달성 기준에서는 남은 항목**이다.

## 완료를 위한 우선순위

1. 최신 회원/인증·대여소 ID·상태·태그 교체 계약을 팀 문서와 DB 설계에 일치시킨다.
2. 서버 인증/인가·물품 조회 및 CRUD·태그 등록/조회/교체 API와 DB 트랜잭션을 구현한다.
3. 관리자 UI를 만들고 사용자/관리자 화면을 실제 API에 연결한다.
4. Java NFC 브리지 및 USB 리더기를 연결하고 UID/중복/미등록/비활성/연결 끊김을 실장비로 검증한다.
5. DB 실행 로그·API 성공/실패·실물 시연·팀 검토 결과를 노션 주차별 완료 기준에 첨부한다.

## 이번 점검의 실행 검증

- TypeScript 검사 및 Vite 프로덕션 빌드: 통과.
- Vitest 모의 서비스 계약 테스트: 20/20 통과.
- Playwright 화면 테스트: 22/22 통과(약 2.9분). 가입·PIN·SMS 오류·브라우저 등록·복구·번호 변경·3분 코드 자동 갱신·모바일 레이아웃·대여/반납·오류 복구를 포함한다.
- 위 테스트는 브라우저 모의 데이터/시뮬레이터 기준이다. 실제 SMS 발송, 서버 HTTP API, PostgreSQL 연결 및 실제 NFC 장비 통과를 의미하지 않는다.
- 실제 DB/백엔드 기동·실장비 테스트는 수행하지 않았다.

이번 작업은 점검이며 기능 코드나 노션 완료 체크를 변경하지 않았다. 보고서를 추가하고 기존 테스트를 실행했다.
