# UI/UX 품질 검수 체크리스트

[현재 설계·디자인 시스템](frontend-redesign-design.md)의 실행용 체크리스트다. 사용자 웹·관리자 웹·키오스크 관련 변경에 적용한다. 체크 표시는 실제 확인한 항목만 한다. 작업 기록에 각 항목의 통과/실패/미검증/해당 없음과 근거를 남긴다. 해당 없음은 사유가 필요하다. 이 빈 양식 자체는 검수 완료 기록이 아니다.

## 준비 및 범위

- [ ] worktree 목록, 관련 status/log, 적용 AGENTS.md·CONTRIBUTING.md와 최신 결정 확인
- [ ] 경로·브랜치·HEAD·미커밋 변경, 대상 화면·기능·기기·제외 범위 기록
- [ ] 기존 사용자 변경과 인증·API·거래·권한 계약 보존 계획 확인
- [ ] 실행 방법, 데이터 출처(fixture/격리 DB/실서버), 안전한 캡처·비밀정보 제외 확인
- [ ] UI 수정이면 가능한 범위에서 수정 전 화면 확보

## 문구·정보·흐름

- [ ] 제목·설명의 중복, 장식 영문·배지·슬로건·불필요 환영/개발 문구 제거 여부 확인
- [ ] 버튼이 실제 행동을 표현하고 용어·날짜·상태명이 일관됨
- [ ] 필수 경고·권한·오류·다음 행동이 누락되지 않음
- [ ] 핵심 정보와 주요 행동을 먼저 발견하고 보조 정보와 구분할 수 있음
- [ ] 관련 정보/버튼이 함께 배치되고 불필요한 단계·확인창이 없음
- [ ] 뒤로가기/상세 닫기 후 검색·필터·선택·스크롤·포커스가 적절히 복원됨

## 배치·간격·시각 스타일

- [ ] 제목·본문·필드·버튼·표 헤더와 데이터·아이콘의 정렬 확인
- [ ] 중첩 카드, 불필요한 컨테이너, 과도한 빈 공간·고정 높이 없음
- [ ] margin/padding/gap 중복과 페이지별 불규칙한 간격 없음
- [ ] 동일 역할의 높이·반경·여백이 일관되고 데이터 양에 맞는 크기/비율 유지
- [ ] 영역별 토큰·최종 computed style·CSS 적용 순서 확인
- [ ] 브랜드·상태색, hover/active/focus/disabled가 의도와 일치
- [ ] 승인 티켓·키오스크 버튼의 예외와 불필요한 장식 확산 구분
- [ ] 실제 이미지/대체 이미지/기본 아이콘이 안정적으로 표시되고 샘플 콘텐츠 없음
- [ ] 표/목록/카드가 업무 목적에 적합하고 주요 정보가 숨지 않음

## 반응형·접근성

- [ ] 사용자·관리자 관련 화면을 320/390/768/1024/1440px에서 확인(해당 범위 선택 근거 기록)
- [ ] 키오스크 변경은 1280×720/1366×768/1920×1080 및 필요한 세로 배치 확인
- [ ] 긴 한글/ID/오류, 빈 데이터·많은 데이터에서 잘림·겹침·의도치 않은 가로 스크롤 없음
- [ ] 모바일 키보드·safe-area·내부 스크롤·고정 메뉴·200% 확대에서 행동 접근 가능
- [ ] 글꼴 로딩 실패 시 대체 글꼴로도 읽고 조작 가능
- [ ] 텍스트·컨트롤·포커스 대비를 실측하고 색 외 상태 표현 확인
- [ ] 키보드 순서·보이는 포커스·모달 포커스 유지와 복귀·Escape 확인
- [ ] 시맨틱 제목/영역·접근 가능한 이름·label·오류 설명 연결 확인
- [ ] 클릭/터치 영역이 영역별 규격을 충족하고 hover 없이도 안내 접근 가능
- [ ] reduced-motion, 로딩/오류 상태 알림, 중복 발화 여부 확인
- [ ] 키오스크 관리자 반전 테마의 텍스트·필드·상태·다이얼로그 가독성 확인

## 상태·기능 보존

- [ ] 초기·로딩·빈 목록·검색 없음·많은 데이터 상태 구분
- [ ] 네트워크/서버 오류, 권한 없음/세션 만료, 재시도·복구 경로 확인
- [ ] 입력 검증·비활성·저장 중·완료 상태와 중복 제출 방지 확인
- [ ] 백그라운드 갱신 중 초안/상세/선택 유지, 실패 시 이전 데이터 표시 정책 확인
- [ ] 카카오 가입/로그인·개인 관리자 인증·권한을 시각 변경으로 손상하지 않음
- [ ] 자동 이용 코드·이미지 우선순위·개별 물품 정책이 최신 계약과 일치
- [ ] 대여/반납은 서버 저장 확인 후 완료, 응답 유실 시 기존 작업 결과 확인 유지
- [ ] 키오스크 숨김 진입·장애 경고·유휴 복귀·진행 중 거래 보호·완료 복귀 유지
- [ ] 웹 태그 비활성/설치형 NFC 활성 구분, 기존 기능·업무 회귀 확인

## 실제 렌더·재검수·문서

- [ ] 자동화 결과 외 실제 캡처/실행 화면을 직접 확인하고 화면·크기·상태 기록
- [ ] 콘솔/pageerror, overflow·실제 요소 크기·간격과 접근성 검사 범위를 기록
- [ ] 관련 빌드·기존 테스트 명령/결과를 기록하고 과거 결과와 구분
- [ ] 발견 문제를 허용 범위에서 수정하고 같은 조건으로 재검수
- [ ] 공통 스타일/컴포넌트 영향이 있는 다른 인터페이스도 회귀 확인
- [ ] 변경 규격·결정·예외·남은 문제를 문서에 반영하고 링크 실존 검증
- [ ] fixture / 실제 API·DB / 설치 앱 / 실물 NFC / 배포·원격 병합 상태를 분리 보고

## 작업 기록 양식

날짜 / 경로 / 브랜치 / 커밋+미커밋 여부 / 대상 화면·상태 / 환경·데이터 출처 / 크기 / 명령·결과 / 캡처 경로 / 직접 본 화면 / 문제·수정·재검수 / 미검증·해당 없음 사유 / 문서 갱신 / 배포 여부를 남긴다. 모든 화면을 보지 않았다면 대표 화면만 보았다고 명시한다.

### 발견 사항과 개선 방향 (아직 미수정)

| 근거 | 관찰·개선 방향 |
|---|---|
| 사용자 CSS `.primary:hover/:active` | 그린 기본 버튼에 과거 파란 상태색이 남음. 승인 브랜드의 상호작용 색을 정하고 실제 hover/active 조합을 확인한 뒤 보정 필요. 이번 캡처는 hover 상태 검증이 아님 |
| 390px 홈 캡처 | 대여 2건 아래 흰 영역이 화면 높이에 맞춰 크게 남음. 고정 메뉴·목록 내부 스크롤은 보존하면서 짧은 목록의 컨테이너 확장 필요성을 검토 |
| 1440px 관리자 물품 캡처 | 긴 물품명에 맞춰 같은 행 카드가 늘어나 짧은 카드 하단에 여백이 생김. 승인 카드 방향을 유지하며 이름 영역·메타데이터 정렬·행 높이를 실제 데이터로 검토. 관찰 자체가 결함 확정은 아님 |
| 1280px 키오스크 캡처 | 반납은 최신 계약상 코드 → NFC인데 시작 버튼은 태그 인식을 강조하며 코드 준비 안내가 대여에만 있음. 반납 첫 행동 안내를 일치시키는 후속 문구 검토 필요 |
| 키오스크 캡처 | 상단 보관소 소제목과 하단 슬로건은 핵심 행동 이해에 필요한지 검토. 서버 확정 전 직접 확인하라는 필수 안내는 보존 |
| CSS 구조 | 전역·영역별 토큰과 후반 승인 스타일이 여러 번 덮어씀. 바로 통합하지 말고 최종 computed style·소비자 영향 확인 후 동일 의미 토큰부터 점진 정리 |
| 문서 구조 | 과거 PIN/SMS·공통 관리자·종류별 목록 기록이 최신 정책과 공존. 이번 진입 문서에 우선순위를 명시했으며 개별 역사 문서를 현재 계약으로 사용하지 않도록 유지 |

미검증: 실측 색 대비, 모든 hover/active/disabled 상태, 모든 화면의 직접 시각 확인, 스크린리더·전체 키보드/200% 확대·가상 키보드·폰트 실패, 키오스크 관리자 반전 테마의 이번 직접 렌더, 전체 기능 회귀·오류/빈 데이터, 실제 카카오·운영 API/DB·실물 NFC·Windows 설치 패키지·Android 실앱. 이번 5개 검사로 전체 접근성/상용 품질 완료를 선언하지 않는다. 배포·운영 데이터 변경 없음. 발견 사항의 수정/재검수는 별도 UI 개선 범위에서 수행한다.
