# 공통 관리자 로그인과 키오스크 태그 등록

TagBack 관리자는 공통 관리자 비밀번호로 로그인해 물품과 운영 현황을 관리합니다.

물품은 관리자 웹에서 등록하고, NFC 태그 연결과 교체는 리더기가 연결된 키오스크의 관리자 모드에서 처리합니다.

사용자의 카카오톡 로그인과 관리자의 공통 비밀번호 로그인은 별도로 운영합니다.

---

## 관리자 기능

### 관리자 웹

- 공통 관리자 비밀번호로 로그인
- 물품 등록·수정·삭제
- 물품 상태 변경
- 물품·태그 연결 상태 조회
- 사용자·대여 현황 및 이용 이력 조회

### 키오스크 관리자 모드

- 태그 등록 대기 물품 조회
- NFC 태그 연결
- 기존 NFC 태그 교체
- 태그 연결 결과 확인
- 관리자 모드 종료

관리자 모드에서는 일반 대여·반납을 동시에 진행하지 않습니다.

---

## 물품 및 태그 등록 절차

### 1. 관리자 웹에 로그인

관리자 웹의 `/admin`에 접속해 공통 관리자 비밀번호로 로그인합니다.

관리자 로그인에는 일반 사용자의 회원가입이나 카카오톡 로그인이 필요하지 않습니다.

### 2. 물품 등록

관리자 웹에서 물품명과 물품 종류를 입력해 물품을 등록합니다.

- 신규 물품은 `TAG_PENDING` 상태로 저장됩니다.
- `TAG_PENDING`은 NFC 태그 등록을 기다리는 상태입니다.
- 태그가 연결되기 전에는 물품을 대여할 수 없습니다.
- 물품 종류는 등록할 때 선택할 수 있도록 미리 준비되어 있어야 합니다.

### 3. 키오스크 관리자 모드에 로그인

NFC 리더기가 연결된 키오스크의 시작 화면에서 **관리자 태그 등록**을 선택합니다.

관리자 웹에서 사용하는 공통 관리자 비밀번호로 로그인합니다.

### 4. NFC 태그 연결

1. 태그 등록 대기 물품을 선택합니다.
2. NFC 태그를 리더기에 인식시킵니다.
3. 물품명, 물품 ID와 태그 UID를 확인합니다.
4. **태그 연결 확정**을 선택합니다.
5. 연결에 성공하면 물품이 `AVAILABLE` 상태로 전환됩니다.

### 5. 관리자 모드 종료

작업이 끝나면 **관리자 종료**를 선택해 키오스크 시작 화면으로 돌아갑니다.

---

## 기존 NFC 태그 교체

기존 물품의 태그를 교체하려면 키오스크 관리자 모드에서 물품을 검색하고 새 태그를 인식합니다.

태그 교체 시 다음 규칙이 적용됩니다.

- 대여 중인 물품의 태그는 교체할 수 없습니다.
- 이미 다른 물품에 연결된 UID는 사용할 수 없습니다.
- 다른 관리자가 먼저 변경한 태그 정보와 충돌하면 변경을 거부합니다.
- 위조되었거나 재사용된 스캔은 거부합니다.
- 점검·수리 상태의 물품은 태그를 교체해도 해당 상태를 유지합니다.

물품명과 물품 종류 수정은 관리자 웹에서 처리합니다.

## 공통 관리자 비밀번호 설정

관리자 비밀번호는 기본값으로 제공되지 않습니다.

비밀번호를 설정하지 않으면 관리자 로그인이 차단됩니다. 실제 비밀번호를 코드, 문서, Git 저장소 또는 스크린샷에 기록하지 않습니다.

### Docker Compose 설정

저장소 루트에서 PowerShell 7로 실행합니다.

```powershell
pwsh -NoProfile -File deploy/compose/Initialize-Compose.ps1

pwsh -NoProfile -File deploy/compose/Set-AdminPassword.ps1

docker compose up -d --build --wait --wait-timeout 240
```

비밀번호 설정 스크립트는 화면에 표시되지 않는 방식으로 비밀번호를 두 번 입력받습니다.

- 비밀번호 길이: 12~128자
- 해시 방식: PBKDF2-SHA256
- 반복 횟수: 600,000회
- 해시 저장 위치: `deploy/compose/local/admin-password-hash`

Compose는 저장된 해시를 secret으로 API에 전달합니다. 초기화 스크립트는 기존 관리자 비밀번호 해시를 덮어쓰지 않습니다.

별도로 Spring Boot를 실행하는 환경에서는 동일한 형식의 해시를 `tagback.admin.password-hash` 설정에 제공해야 합니다.

### 관리자 비밀번호 변경

비밀번호 설정 스크립트를 다시 실행한 뒤 API를 재생성합니다.

```powershell
pwsh -NoProfile -File deploy/compose/Set-AdminPassword.ps1

docker compose up -d --build --force-recreate --wait api
```

새 비밀번호 설정으로 API가 시작되면 이전 관리자 세션은 사용할 수 없습니다.

운영 환경에서 비밀번호를 변경하기 전에는 해당 환경의 설정과 재시작 절차를 확인해야 합니다.

## 관리자 인증 정책

### 관리자 웹

- 사용자 로그인과 분리된 관리자 세션을 사용합니다.
- 관리자 세션 쿠키에는 `Secure`, `HttpOnly`, `SameSite=Strict` 설정이 적용됩니다.
- 웹 관리자 세션은 발급 후 30분이 지나면 만료됩니다.
- 관리자 웹은 HTTPS 환경에서 사용합니다.

### 키오스크 관리자 모드

- 키오스크는 웹과 분리된 관리자 세션을 사용합니다.
- 키오스크 관리자 세션은 발급 후 10분이 지나면 만료됩니다.
- 조작이 없으면 5분 후 관리자 모드가 종료됩니다.
- 저장 결과 확인 중에는 진행 중인 요청을 보존하고, 필요한 경우 다시 인증합니다.

Windows 설치형 호스트는 관리자 토큰을 메인 프로세스 메모리에 보관하고 화면에는 임의의 핸들만 전달합니다. 관리자 비밀번호와 토큰은 로컬 스토리지에 저장하지 않습니다.

### 로그인 제한

공통 관리자 비밀번호 로그인은 서버 전체에서 분당 10회로 제한됩니다. 성공한 시도도 제한 횟수에 포함됩니다.

기존 사용자 계정의 `ADMIN` 역할만으로는 공통 관리자 API에 접근할 수 없습니다.

## 태그 스캔과 저장 정책

태그 연결과 교체에는 다음이 필요합니다.

- 유효한 키오스크 관리자 세션
- 신뢰된 리더기에서 발생한 서명된 NFC 스캔
- 연결하거나 교체할 물품 정보

기존 태그 API에 UID를 직접 입력하는 쓰기 요청은 차단됩니다.

태그 연결, 물품 상태 변경, 감사 기록과 작업 응답은 하나의 트랜잭션으로 저장합니다.

응답이 유실되었을 때는 같은 작업 ID와 요청 내용으로 결과를 다시 확인합니다. 처리되지 않은 스캔이 만료된 경우에는 미적용 상태를 확인한 뒤 태그를 다시 인식할 수 있습니다.

---

## 감사 기록

관리자 태그 작업과 관련된 감사 정보가 저장됩니다.

기록에는 작업에 따라 다음 정보가 포함될 수 있습니다.

- 관리자 세션
- 작업 시각
- 리더기
- 물품
- 변경 전·후 태그 UID

공통 비밀번호 방식이므로 감사 기록만으로 실제 작업자를 개인별로 식별하지는 못합니다.

운영 환경에서는 관리자 비밀번호와 키오스크 장치의 접근 권한을 별도로 관리해야 합니다.

---

## 데이터베이스

공통 관리자 기능은 관리자 세션, 로그인 제한, 감사 및 태그 작업과 관련된 DB 스키마를 사용합니다.

Spring Boot 실행 시 Flyway가 해당 버전의 미적용 마이그레이션을 적용합니다. 실행할 코드에 포함된 마이그레이션과 기존 DB의 적용 이력을 확인해야 합니다.

앱 이미지를 이전 버전으로 되돌려도 DB 마이그레이션은 자동으로 되돌아가지 않습니다. 운영 환경의 변경 전에는 DB 백업과 복원 절차를 준비합니다.

---

## 검증 범위

기존 통합 검증에서는 공통 관리자 로그인, 인증 채널 분리, 세션 만료·로그아웃, 로그인 제한, 태그 등록·교체와 동일 요청 복구 등을 테스트했습니다.

실제 PostgreSQL을 사용하는 관리자 통합 테스트와 프론트엔드 화면 fixture 테스트 기록이 있습니다.

다음 항목은 별도 검증이 필요합니다.

- 실제 NFC 리더기와 실물 태그를 이용한 등록·교체
- 물리 장치를 포함한 전체 대여·반납 흐름
- 운영 데이터와 운영 환경에서의 업무 검증
- 다른 PC에서의 Windows 키오스크 설치 및 인수 확인

화면 fixture나 가상 NFC 이벤트를 이용한 테스트는 실제 리더기와 서버를 함께 연결한 검증을 대신하지 않습니다.
