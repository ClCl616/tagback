# TagBack 리디자인 화면 상태 및 디자인 명세

2026-11-06 설계 기록. 사용자 웹·관리자 웹·Windows 및 Android 키오스크의 화면, 상태, 계약과 디자인 규칙을 보존한다. 아래 단계별 진행 문구는 명세 작성 당시 기록이며, 최신 구현·검증·남은 작업은 [진행 보고서](frontend-redesign-progress.md)를 우선한다. 시안 이미지와 로컬 전용 문서는 저장소에 포함하지 않는다.

## 사용자 웹 세부 화면 및 상태 명세

다음은 1단계에서 작성한 리디자인 설계 기준이다. 현재 구현을 설명하는 부분은 별도 표시하며, 정책·API 의존 항목은 해결 전 정상 기능으로 가정하지 않는다. 화면 ID는 문서상 식별자이고 URL 확정이 아니다. 휴대폰·PC에서 같은 데이터와 상태를 사용한다.

### 인증 및 시작

| ID | 화면과 진입 | 정상 동작과 다음 이동 | 예외 상태와 복구 |
|---|---|---|---|
| U01 | 시작·비로그인 홈 | 로그인·회원가입·물품 둘러보기. 로그인 상태 확인 후 개인 홈 또는 비로그인 홈 표시 | 세션 조회 실패는 비로그인 확정과 구분. 연결 실패 안내와 다시 시도 제공 |
| U02 | 일반 로그인 | 전화번호·6자리 PIN으로 인증. 가입용 PIN 규칙을 기존 PIN 로그인에 새로 적용하지 않음. 성공 시 유효한 사용자 웹 복귀 목적지, 없으면 홈 | 전화번호 형식 오류는 필드 안내. PIN 오류 시 PIN만 지우고 재입력. 없는 계정은 회원가입 안내. 서버 제한 시간·잠금 상태에 맞춰 입력 및 제출 제한 |
| U03 | 등록 브라우저 로그인 | 서버가 유효한 등록을 확인한 경우 마스킹 번호와 PIN 입력 표시. 다른 계정 사용으로 U02 이동 | 등록 만료·해제는 U02로 전환. 통신 실패를 등록 없음으로 단정하지 않음. 자동 제출을 유지할 경우 버튼 제출과 중복 요청 방지 |
| U04 | 회원가입 기본 정보 | 이름·직업 입력 후 본인 인증. 시안의 소속/직업은 실제 지원 필드인 직업으로 통일 | 공백 입력·미선택 안내. 이전/다음 이동 시 비밀값 외 초안 유지. 지원되지 않는 학번·소속 필드를 추가하지 않음 |
| U05 | 회원가입 전화번호·SMS 인증 | 발송 전 → 발송 중 → 코드 입력 → 검증 중 → PIN 설정. 발송 버튼과 인증 버튼을 상태별로 구분 | 잘못된 번호·인증번호, 기존 가입 번호, 발송 제한, 인증번호 만료, 통신 실패를 구분. 기존 가입자는 로그인으로 안내. 재발송 가능 시각과 만료 시각은 서버 값 사용 |
| U06 | PIN 최초 설정 | 6자리 PIN 안내 후 입력, 유효하면 U07로 이동. 회원가입 진행은 기본 정보 → 본인 인증 → PIN 설정 → PIN 확인의 4단계 | 같은 숫자 3회 연속·전체 6자리 오름/내림 연속 등 기존 정책 위반 안내. PIN을 지우고 재입력. 승인 이미지의 두 PIN 필드는 요약 표현이며 실제 단계는 분리 |
| U07 | PIN 확인 | 최초 PIN 재입력 일치 후 가입 요청. 서버 성공 확인 후 로그인 결과에 따라 홈 또는 로그인 안내 | 불일치면 확인 입력만 지우고 재입력. PIN 수정은 U06. 저장 중 중복 제출 차단. 응답 유실은 U10으로 이동하며 가입 완료로 표시하지 않음 |
| U08 | PIN 재설정 본인 인증 | 전화번호·SMS 인증 → 새 PIN 설정 → 확인. 인증 UI는 U05, 설정 UI는 U06·U07 재사용 | 없는 계정·복구 불가·인증 만료를 구분. 재설정 중 인증 증명이 만료되면 본인 인증부터 다시 진행 |
| U09 | PIN 재설정 완료 | 서버가 변경 성공을 확인한 경우만 완료 표시. 새 PIN으로 로그인 버튼 | 기존 로그인 세션이 존재한다는 이유만으로 재설정 완료로 간주하지 않음 |
| U10 | 인증 처리 결과 불명확 | 결과 확인 안내, 지원되는 결과 조회·기존 요청 재시도 경로 사용 | 새 가입·변경을 자동 반복하지 않음. 확인 실패 시 기존 계정 로그인 또는 인증 재시작 안내. 중복 요청 방지 키 등 기존 복구 로직 유지 |

SMS 남은 시간과 재발송 대기는 서로 다른 값이다. 새로고침·전화번호 변경·뒤로가기에서 다른 번호의 인증을 재사용하지 않는다. PIN은 마스킹하고 장기 저장하지 않으며, 인증 오류 메시지는 원인을 알 수 있는 위치에 표시한다. 문자 발송 성공과 문자 수신·본인 인증 완료도 구분한다.

### 홈과 물품 탐색

| ID | 화면과 진입 | 정상 동작과 다음 이동 | 예외 상태와 복구 |
|---|---|---|---|
| U11 | 로그인 홈 | 이름, 코드 발급 진입, 바로가기, 내 대여 요약. 홈의 코드 카드와 코드 화면은 같은 유효 코드를 공유하는 방향으로 설계 | 대여 0건은 빈 상태. 조회 실패를 0건으로 표시하지 않음. 요약·프로필 일부 실패는 해당 영역 재시도. 홈 방문만으로 반복 발급하지 않음 |
| U12 | 물품 목록 | 검색·카테고리·현재 대여소 표시, 실제 재고. 선택하면 U13. 목록 복귀 시 검색·필터·스크롤 보존 | 로딩, 전체 물품 없음, 검색 결과 없음, 서버 실패 구분. 검색 결과 없음에는 검색 지우기·필터 초기화. 이미지 없으면 공통 물품 아이콘. 단일 대여소는 선택 가능한 여러 곳처럼 표현하지 않음 |
| U13 | 물품 상세 | 물품 종류 정보·대여 가능 수량·현재 대여소·키오스크 이용 안내. 코드 버튼은 로그인 필요 시 U02 경유 후 복귀 | 삭제·없는 대상은 목록으로. 재고 0이면 대여 불가와 다른 물품 보기 제공. 재고 확인은 예약이 아니며 최종 대여 가능 여부는 키오스크와 서버가 확인 |

재고가 없는 물품의 상세에서 대여 목적의 코드 발급을 강조하지 않는다. 이용 코드는 반납에도 쓰므로 홈·내 대여의 발급 진입은 별개로 유지한다. 물품 선택이 웹 예약이나 특정 물품 확정을 의미하지 않도록 문구를 통일한다.

### 이용 코드

| 상태 | 화면 표현 | 가능한 행동 및 전환 |
|---|---|---|
| U14 미발급 | 코드 대신 이용 안내와 이용 코드 발급 버튼 | 사용자 클릭으로 발급. 비로그인은 로그인 경유 |
| 발급 중 | 버튼 비활성, 발급 중 표시. 이전 유효 여부가 불명확한 코드는 노출하지 않음 | 요청 하나만 진행, 성공 응답의 6자리 값과 만료 시각으로 전환 |
| 사용 가능 | 숫자 6자리, 남은 시간, 본인만 사용 안내, 대여·반납 절차 | 코드는 마스킹 없는 현재 값만 표시. 화면 이동·포커스 복귀 때 무조건 새 코드 발급하지 않도록 구현 설계 필요 |
| 만료 | 숫자 숨김, 시간이 만료되었어요, 새 코드 발급 버튼 | 재발급은 명시적 조작으로 처리하는 리디자인 제안. 기존 자동 재발급 동작 변경이므로 API 계약 확인 후 적용 |
| 사용 완료 | 서버가 소비 사실을 확인할 수 있을 때만 숫자 숨김과 사용한 코드 안내 | 코드 사용은 대여·반납 저장 완료와 다름. 완료 여부는 내 대여·이력을 조회. 현재 웹 어댑터만으로 소비 상태 감지 불가 |
| 발급 실패 또는 결과 불명확 | 발급 결과를 확인하지 못했어요. 다시 시도 안내 | 단순 조회 버튼처럼 표현하지 않음. 재요청 시 기존 유효 코드 반환 여부·이전 코드 무효화 정책을 확인한 뒤 복구 동작 확정 |
| 인증 만료 | 코드 숨김, 다시 로그인 안내 | 로그인 후 새로 확인. 사용자 전환 시 이전 사용자 코드를 재사용하지 않음 |

현재 `rentalCodeHttp.ts`는 발급 POST 결과를 `used: false`로 반환하고, 기존 CodePage는 진입·새로고침·포커스 복귀 때 발급 경로를 호출하며 만료 시 다시 로드한다. 따라서 현재 구현이 코드 상태 조회 API를 제공한다고 해석하지 않는다. 명시적 발급·재발급 UI, 홈과의 코드 공유, 소비 감지는 구현 전 서버 계약 대조 항목이다.

대여 안내는 코드 입력 → 물품 종류 선택 → NFC 인식 → 대여 확정 순서다. 반납 안내는 NFC 인식 → 정상·손상 선택 → 본인 코드 입력 → 반납 확정 순서다. 현재 모바일 안내에 남아 있는 물품 선택 우선 문구는 구현 시 확정 흐름에 맞춰 수정한다.

### 대여와 계정 관리

| ID | 화면과 진입 | 정상 동작과 다음 이동 | 예외 상태와 복구 |
|---|---|---|---|
| U15 | 내 대여 현황 | 진행 중인 대여와 반납 예정일 표시, 선택 시 U16. 서버 상태를 기준으로 연체 구분 | 대여 없음은 물품 찾아보기. 조회 실패는 재시도. 연체는 색뿐 아니라 반납 기한 초과 텍스트 제공. 날짜만으로 임의의 제재·벌금 기능을 만들지 않음 |
| U16 | 대여 상세 | 물품·대여 시각·반납 예정 시각·대여소·상태, 키오스크 반납 안내, 코드 발급 진입 | 본인 소유 여부는 서버 접근 통제. 없는 내역·권한 없음·조회 실패 구분. 이미 반납됐으면 이력 상태로 갱신. 웹에 반납 확정 버튼 없음 |
| U17 | 이용 이력 및 상세 | 완료된 대여·반납 시각 표시, U16 구성 재사용. 연체 반납·손상 접수는 실제 응답이 지원할 때 표시 | 기록 없음과 검색 결과 없음 구분. 삭제된 물품도 대여 기록의 보존된 이름을 활용. 기간 필터는 기준 날짜·전체 데이터 범위 확인 후 구현하며 예시 이미지 필터를 그대로 복제하지 않음 |
| U18 | 내 정보 | 이름·직업·대여 요약, PIN 재설정, 이용 이력, 로그아웃 | 정보 실패를 빈 이름/0건으로 대체하지 않음. 전화번호 변경·프로필 수정·알림 설정은 지원 확인 없이 활성화하지 않음 |
| U19 | 로그아웃 처리 | 명시적 클릭 → 처리 중 → 성공 확인 → 개인 데이터·코드 제거 후 비로그인 홈 | 응답 유실 시 개인 데이터는 가리고 세션을 재확인. 서버 로그아웃 완료를 임의 단정하지 않음. 재시도 가능 |

대여 상세는 목록에서 얻은 데이터 재사용과 직접 진입·새로고침 시 복구 방법을 함께 구현한다. 서버가 제공하지 않는 상세 API를 이미 존재한다고 가정하지 않는다. 현재 대여 어댑터는 서버 overdue를 수신하므로 리디자인에서는 이를 우선 사용하도록 검토한다. 반납 손상 상태는 현재 어댑터 매핑이 없는 만큼 별도 확인 항목이다.

### 공통 상태 표현과 복귀 규칙

| 상황 | 표현 위치와 문구 기준 | 복구 및 완료 기준 |
|---|---|---|
| 최초 로딩 | 페이지 또는 카드 영역의 로딩 표시 | 데이터 도착 전 0건·대여 불가로 표시하지 않음 |
| 필드 오류 | 해당 입력 아래 짧은 원인, 오류 필드로 포커스 | 수정 가능한 입력은 유지. PIN 오류는 비밀값 재입력 |
| 조회 연결 실패 | 해당 콘텐츠 영역에 연결 실패·다시 시도 | 오류 팝업을 닫아도 재시도 진입점이 남음 |
| 인증 만료 | 개인 데이터와 코드 가림, 다시 로그인 | 유효한 내부 복귀 목적지를 보존. 임의 외부 URL로 이동하지 않음 |
| 없는 대상 | 물품/내역을 찾을 수 없어요 | 이전 목록으로 이동 |
| 결과 불명확 | 저장 성공 여부를 확인할 수 없음을 설명 | 결과 조회가 실제 지원되는 작업에만 결과 확인 버튼. 일반 POST를 조회로 위장하지 않음 |
| 저장 중 | 버튼 비활성·진행 표시 | 중복 클릭·Enter·자동 제출이 같은 요청을 반복하지 않음 |
| 성공 | 서버 응답 확인 후 완료 문구 | 코드 발급 성공·인증 성공·대여 저장 성공을 서로 구분 |

모바일과 PC의 상태 의미·버튼 문구는 동일하게 유지한다. 모바일은 한 열 중심, PC는 승인 시안의 사이드바·목록과 상세 패널을 사용하되 포커스 순서와 오류 복귀를 유지한다. 구체적인 시각·반응형·접근성 기준은 아래 2단계 명세를 따른다.

### 보충 시안과 이후 검증 기준

기본 4장은 다시 생성하지 않는다. 새로운 배치 확인이 필요한 PIN 재입력과 대표 예외 상태를 `05-user-web-detail-states.png` 한 장으로 보충한다. 내용은 PIN 확인 불일치, SMS 만료·재발송 대기, 이용 코드 만료, 대여 없음, 연결 실패·재시도다. 보충 시안은 새 검토안이며 기본 시안 승인에 자동 포함되지 않는다.

보충 이미지는 기본 시안과 같은 폴더에 저장했고 `detail-states-prompt.json`에 생성 프롬프트를 보존했다. 이미지의 SMS 마스킹 점 개수는 실제 입력 길이가 아니다. 구현은 숫자 6자리이며 SMS는 입력값 확인이 가능하도록 표현하고 PIN만 마스킹한다. 빈 PIN 상태의 제출 버튼은 비활성화하거나 검증 처리한다. 이미지보다 본문의 상태·입력 규칙을 우선한다.

단순 로딩·성공·필수 입력·계정 없음·세션 만료는 위 명세와 공통 컴포넌트로 설계하고 각각 별도 이미지를 만들지 않는다. 등록 브라우저 로그인은 같은 인증 틀에 마스킹 번호와 계정 전환을 적용한다. PC 인증·내 정보는 아래 공통 규칙의 중앙 폼·카드 배치를 따른다.

1단계에서 정의한 후속 검증 시나리오:

- 가입 정상 경로, 기존 가입 번호, SMS 오입력·만료·재발송 제한, 새로고침 후 재개.
- PIN 정책 위반·확인 불일치·설정 수정, 재설정 증명 만료, 응답 유실 후 중복 처리 방지.
- 일반 로그인·등록 브라우저 로그인·다른 계정 사용·세션 만료와 원래 화면 복귀.
- 목록 검색·필터·상세 복귀, 재고 없음·물품 삭제·이미지 없음, 서버 장애와 빈 상태 구분.
- 코드 명시적 발급·만료·재발급·발급 실패, 화면 전환 시 불필요한 발급 방지, 사용 여부를 추정하지 않는 표시.
- 대여 없음·연체·반납 후 갱신·이력 상세, 손상 정보가 없을 때 임의 표시 금지.
- 내 정보·로그아웃, 사용자 전환 시 이전 데이터 제거, 모바일/PC 키보드·포커스·오버플로 확인.

이 목록은 테스트 실행 결과가 아니라 이후 구현·검증의 수용 기준이다. 1단계의 API 의존 미결 사항은 코드 재요청 정책·소비 확인, 상세 직접 진입 데이터, 이력의 손상 정보·기간 필터다. 서버 변경이나 기능 확장을 이번 문서 작업에서 확정하지 않는다.

## 사용자 웹 공통 디자인 규칙 v1

2026-11-06 2단계 설계 산출물. 승인된 기본 시안의 시각 방향을 실제 구현 가능한 값으로 구체화했다. 아래 수치는 이미지에서 추출한 측정값이 아니라 이번 설계에서 선택한 기준이다. 제품 CSS·컴포넌트에는 아직 적용하지 않았다. 이 단계는 사용자 웹에 적용하며 관리자 웹·키오스크의 크기와 레이아웃은 별도로 설계한다.

기본 테마는 라이트 모드만 설계한다. 본문은 투명도 없이 지정 색으로 표시한다. 화이트 텍스트/brand 대비는 약 5.61:1, text-secondary/화이트는 6.18:1, text-secondary/canvas는 5.77:1이다. 성공·오류·주의 글자와 각 연한 배경 대비는 각각 4.76:1, 6.05:1, 6.84:1로 계산했다. 프로젝트의 일반 텍스트 대비 목표는 4.5:1 이상이다. 실제 브라우저의 혼합·disabled·focus·hover 조합은 구현 후 검증하며 접근성 인증 완료를 의미하지 않는다.

홈 코드 발급 영역만 brand-pressed → brand의 약한 그라데이션을 허용한다. 강조색이 없는 장식 그림자를 본문 대비로 계산하지 않는다. 연체·오류는 붉은색과 함께 텍스트·아이콘으로 의미를 전달한다.

### 글꼴과 문구

글꼴은 기존 프로젝트에서 사용하는 Noto Sans KR을 기준으로 하고, 대체 글꼴은 맑은 고딕·시스템 sans-serif를 사용한다. 새 유료 글꼴을 추가하지 않는다. 사용 가능한 글꼴 파일과 로딩 방식을 구현 시 확인하고 로딩 실패에도 텍스트가 보이게 한다. 모든 크기는 아래 px 값을 기준으로 rem으로 구현하며 브라우저 확대를 막지 않는다.

| 용도 | 모바일 크기 / 행간 | PC 크기 / 행간 | 굵기 |
|---|---|---|---|
| 홈 인사·주요 제목 | 28 / 38 | 32 / 44 | 700 |
| 일반 페이지 제목 | 24 / 34 | 28 / 40 | 700 |
| 섹션 제목 | 20 / 28 | 20 / 28 | 700 |
| 카드 제목 | 18 / 26 | 18 / 26 | 700 |
| 본문·입력·버튼 | 16 / 24 | 16 / 24 | 400·500·600 |
| 보조 설명·라벨·표 | 14 / 22 | 14 / 22 | 400·500 |
| 하단 메뉴·배지 | 12 / 18 | 12 / 18 | 600 |
| 이용 코드 | 44 / 56 | 48 / 60 | 700 |

이용 코드는 tabular-nums 숫자 정렬을 적용하고 표시상 3자리씩 나눌 수 있으나 실제 값은 숫자 6자리다. 좁은 320px 화면에서는 코드 크기를 36px까지 줄인다. 카운트다운 폭을 고정해 숫자 변경 시 흔들림을 막는다. 한글 제목은 단어 단위 줄바꿈을 우선하고, 긴 물품명·ID는 컨테이너 밖으로 넘치지 않게 줄바꿈한다. 핵심 날짜·상태를 말줄임표로 숨기지 않는다.

사용자 문구는 기존의 해요체를 유지한다. 주요 명칭은 물품 조회, 대여 내역, 이용 이력, 내 정보, 이용 코드로 통일한다. 대여 내역은 진행 중 대여, 이용 이력은 완료 기록이다. 재시도 버튼은 행동에 따라 다시 시도 / 새 코드 발급 / 다시 로그인 / 처리 결과 다시 확인으로 구별한다. 날짜는 Asia/Seoul 기준이며 상세에는 연월일과 시각을 표시한다. 대여 기간·반납 예정일은 이미지의 3일 예시가 아니라 서버 값을 사용한다.

### 화면 크기별 구성

뷰포트가 아니라 실제 콘텐츠가 확보할 수 있는 폭도 함께 고려한다. 아래 경계값을 v1 기준으로 쓰며 확대·긴 텍스트에서 겹침이 발생하면 더 단순한 배치로 전환한다.

| 구간 | 메뉴와 공통 틀 | 화면 배치 |

| 320~767px | 64px 상단 헤더, 64px 하단 메뉴와 safe-area 여백 | 한 열, 인증 폼은 가로 전체. 물품은 한 열 카드, 대여도 카드. 상세는 전체 페이지 |
| 768~1023px | 상단·하단 메뉴 유지, 콘텐츠 최대 880px 중앙 정렬 | 물품 2열, 홈 주요 영역은 한 열, 상세는 별도 페이지. 긴 목록은 카드 유지 |

홈의 3개 바로가기는 각 항목 너비 96px 이상이면 3열로 유지하고 공간이 부족하면 한 열 목록으로 전환한다. 메뉴 텍스트는 생략하지 않는다. 모바일 하단 메뉴는 각 항목 폭을 균등 분배하며 44px 이상의 조작 영역을 보장한다. 본문 아래에는 하단 메뉴 높이+safe-area+16px 여유를 확보한다.

인증 화면에는 앱 하단 메뉴·PC 사이드바를 표시하지 않는다. PC 인증 폼은 최대 440px, 카드 포함 최대 480px로 중앙에 두고 위쪽에 브랜드와 뒤로가기를 배치한다. 세로 공간이 짧으면 중앙 고정을 풀어 상단부터 스크롤한다. 모바일 인증 입력 시 가상 키보드가 버튼·오류를 가리지 않도록 폼 자체가 스크롤된다.

PC 내 정보는 최대 800px의 카드 영역으로 구성하고 요약은 2열, 설정 항목은 한 열로 유지한다. 코드 화면은 최대 560px 중앙 카드, PC 홈의 보조 코드 카드는 같은 내용의 축약형이다. 화면마다 별도 코드 상태를 만들지 않는다.

모바일에는 표 가로 스크롤을 기본 사용 방식으로 강요하지 않고 라벨이 있는 카드로 전환한다. PC 표는 이름·대여일·반납 예정/완료일·상태를 우선한다. 실제 내용이 충분히 들어갈 때만 표를 사용하고 중요한 열을 숨기지 않는다. 페이지 자체의 가로 스크롤은 허용하지 않는다.

아이콘은 현재 프로젝트의 lucide 계열을 유지하고 20~24px, stroke 1.75~2 기준으로 통일한다. 장식 아이콘은 보조기기에서 숨긴다. 물품 사진이 없으면 동일 크기의 종류별 그림이나 일반 물품 아이콘을 사용한다. 시안의 제품 사진을 실제 보유 모델로 단정하지 않는다. 이름이 함께 있는 장식 썸네일은 불필요한 중복 읽기를 피한다.

### 내비게이션과 상호작용

- 현재 메뉴는 brand 색과 연한 배경 또는 활성 아이콘으로 표시하고 aria-current 등으로 현재 위치를 전달한다. 일반 링크는 실제 이동, 버튼은 동작에 사용한다.
- 이용 코드는 별도 하단 탭이 없으므로 코드 페이지에서 물품 탭을 임의 활성화하지 않는다. 이용 이력은 대여 내역의 하위 화면으로 취급해 모바일 대여 내역 탭을 활성화하고 PC는 이용 이력 메뉴를 활성화한다.
- 제목과 뒤로가기는 상세·인증 화면의 일정한 위치에 둔다. 목록으로 돌아갈 때 검색·필터·스크롤·선택 상태를 복원한다.
- 페이지가 바뀌면 주요 제목 또는 main으로 포커스를 이동하고, 뒤로가기에서는 기존 조작 위치를 복원한다. 카드 목록 갱신만으로 포커스를 갑자기 옮기지 않는다.
- 기본 액션은 화면 콘텐츠 흐름 안에 둔다. 모바일에서 버튼을 고정해야 할 때는 하단 메뉴·safe-area·키보드와 겹치지 않도록 공간을 예약한다.
- 삭제·취소 등의 확인창은 열기 전 요소를 기억하고 닫으면 복귀한다. 모달 안에 포커스를 유지하고 배경 조작을 막으며 Escape 닫기와 명확한 닫기 버튼을 제공한다. 서버 요청 중에는 닫기와 요청 취소가 같은 의미가 아님을 구분한다.

### 접근성과 움직임

프로젝트 목표는 일반 텍스트 대비 4.5:1 이상, 큰 텍스트·필수 비텍스트 조작 표시 대비 3:1 이상, 조작 영역 최소 44×44px이다. focus-visible은 3px brand 바깥선과 2px 흰색 간격을 기본으로 해 파란 버튼에서도 구분되게 한다. 카드 장식 경계와 실제 입력 컨트롤 경계를 구별한다.

화면당 주요 h1 하나, 의미 있는 제목 단계, main/nav/form/label 구조를 사용한다. 키보드만으로 모든 동작을 수행할 수 있어야 하고 포커스를 숨기지 않는다. 200% 확대 및 폭 320px에서 내용을 읽고 조작할 수 있도록 고정 높이를 피한다. 상태·오류·선택을 색에만 의존하지 않는다.

버튼 색·그림자 전환은 120~160ms, 패널은 최대 200ms의 짧은 전환만 사용한다. prefers-reduced-motion에서는 비필수 전환·skeleton 맥동을 없앤다. 카운트다운을 매초 스크린리더로 읽지 않고 만료·발급 완료 등 의미 있는 전환만 안내한다. 오류는 사용자 행동 후 필요한 경우 즉시 알리고 동일 메시지를 반복 발화하지 않는다.

### 구현 인계 및 2단계 확인 범위

색상·간격·글꼴은 공통 토큰으로 관리하고 사용자 웹 루트에 범위를 제한한다. 기존 전역 CSS를 일괄 교체해 관리자·키오스크 화면까지 바꾸지 않는다. 공유 컴포넌트 변경 시 다른 영역 영향은 별도로 검토한다. 기능 코드와 스타일 작업을 구분하되 인증·서버 완료 판정 로직을 시각 시안에 맞춰 단순화하지 않는다.

우선 구현할 공통 묶음은 사용자 웹 틀·메뉴 → 버튼·필드·PIN 입력 → 카드·배지·상태 안내 → 모달·상세 패널이다. 이후 3단계의 인증 → 홈·물품·코드 → 대여·이력·내 정보 순서에 적용한다.

2단계에서는 승인 이미지와 명세의 역할·컴포넌트 일관성을 대조하고 지정된 색 조합의 수학적 대비만 확인했다. 브라우저 렌더링, 글꼴 로딩, 터치·키보드, 실제 화면 폭, API·기능 회귀 테스트는 아직 수행하지 않았다. 구현 후 320·390·768·1024·1440px, 긴 이름·오류 문구, 200% 확대, 키보드, 감소된 동작 설정을 검증한다. 각 화면에서 기본/빈/오류/로딩/인증 만료 상태를 확인하며 API 의존 미결 항목은 1단계 목록대로 유지한다.

### 범위와 확인 근거

2026-11-06 작성. 관리자 웹의 설계 명세이며 제품 구현 완료 기록이 아니다. 기준 시안은 admin-web-flow-v1의 01~04다. 기존 기능을 유지하며 목록→상세→작업→결과 확인의 흐름으로 구성한다. 이미지의 여러 카드·모달은 서로 다른 화면 상태를 비교한 것이며 실제로 동시에 열지 않는다.

로그아웃은 운영자 메뉴에서 제공하고 세션 종료 후 관리자 데이터와 상세를 초기화한다. 인증 세션이 살아 있는지 알 수 없는 통신 오류는 로그아웃 성공으로 표시하지 않는다. 등록·수정·상태 변경은 별도 모달, 목록 상세는 패널을 기본으로 한다. 저장 중 모달 닫기와 중복 제출을 막되 요청이 끝나거나 타임아웃이 확인되면 복구 동작을 제공한다. 서버 작업 성공 후 목록 재조회만 실패한 경우 “저장 완료, 목록 갱신 실패”를 구분하고 저장을 다시 보내지 않는다.

### 구현 순서 및 완료 기준

1. 관리자 인증 경계·레이아웃·토큰·공통 상태 및 기존 주소 호환.
2. 현황·물품 목록/상세·등록/수정/상태/삭제와 저장 결과 확인.
3. NFC 연결·리더기 상태·부분 성공·불명확 응답 복구.
4. 대여/연체/이용 이력·사용자 조회 및 관련 내역 연결.
5. fixture 기반 회귀·반응형·키보드 검증 후 실제 서버/DB·NFC 검증을 별도 수행.

구현 검증에서는 USER가 관리자 API를 요청하지 않는지와 서버의 403, 세션 만료 시 데이터 제거, 늦은 응답의 계정 혼입 방지, 전체 페이지 검색·일치하는 집계, 필터 변경/뒤로가기, 중복 저장 차단, 생성 응답 유실, 태그 연결만 재시도, UID 중복·리더기 단절, 상태 충돌, 삭제 제한, 반환 기록의 시간·연체 표시를 확인한다. 읽기 실패·빈 목록·부분 응답·저장 성공 후 조회 실패를 각각 검사한다.

화면 검증은 320·390·768·1024·1440px, 200% 확대, 긴 이름/UID, 키보드·모달 포커스·감소된 동작을 포함한다. 기존 사용자 웹과 키오스크 회귀도 확인한다. 현재 단계에서는 이 검증을 실행하지 않았으며 기존 사용자 웹 테스트 결과를 관리자 리디자인 검증으로 재사용하지 않는다.

### 상태 전이와 입력 보존

대여: K02 → K03 → K04 → K05 → K06 → K07 → K08 → K02.
반납: K02 → K09 → K10 → K11 → K12 → K13 → K14 → K02.
K15는 K07/K13의 결과 불명확 상태다. 성공 확인 시 원래 완료 화면, 서버가 명확히 거부한 경우에만 오류별 안전한 복귀 경로를 적용한다. 연결이 복구됐다는 이유만으로 저장 성공을 가정하지 않는다.

| 이동/사건 | 보존·초기화 기준 |
|---|---|
| 대여 확인→다시 스캔 | 유효한 grant·종류는 유지 가능, 이전 실물 선택은 해제 |
| 종류 변경 | 이전 스캔 물품·완료 후보 초기화 |
| 반납 코드→상태 수정 | 같은 유효 티켓·실물만 유지, 선택 상태 변경 시 최종 확인 갱신 |
| 반납 재인식 | 이전 티켓·proof·코드·상태 초기화 후 새 대상 확인. 이전 사용자 증명이 새 대상에 섞이지 않음 |
| 동일 태그 반복 신호 | 기존 중복 억제와 제거 이벤트 계약 유지. 스캔 단계 외 신호는 선택·저장 동작을 바꾸지 않음 |
| 취소/일반 유휴 종료/완료 복귀 | 이용 코드·grant·실물·상태·일반 화면 오류 제거, 비동기 응답 세대 무효화 |
| 확정 요청 전송 | 요청 키·실물·인증 문맥·상태를 고정. 연타·Enter·리더기 신호로 중복 호출 금지 |
| 응답 불명확 | 고정한 요청 문맥 유지. 코드 수정·키 갱신·다른 물품 처리 금지. 서버가 명확히 거부한 후 수정 시 새 작업으로 구분 |
| 앱 백그라운드/절전 복귀 | 연결·grant·티켓 유효성 재평가. 남은 시간이 계속 멈춰 있었다고 가정하지 않음. 미확인 요청이 있으면 복구 화면 우선 |

이용 코드·grant·proof·개인 정보는 일반 로그·주소·분석 이벤트·평문 영구 저장소에 남기지 않는다. 실행 중 복구에는 필요한 메모리 문맥을 보존한다. 앱 강제 종료 후 자동 복구를 보장하려면 플랫폼 보안 저장 및 서버 복구 계약을 별도 설계해야 한다. 현재 메모리 기반 웹 로직을 내구성 있는 복구 구현으로 표현하지 않는다.

### 시간 규칙

- 현행 일반 유휴 시간 180초, 완료 자동 복귀 12초를 구현 시작값으로 유지한다. 시안의 “20초”는 유휴 만료 전 경고 구간의 v1 제안값이며 전체 이용 제한 시간을 20초로 바꾸는 뜻이 아니다.
- 계속 이용은 유휴 시간만 갱신한다. 서버 이용 코드·grant·스캔 티켓의 유효 시간은 연장하지 않는다.
- 60초 반납 스캔 티켓과 증명 수명은 서버 계약을 따른다. 최종 확인 단계를 넣더라도 백엔드 시간을 임의 연장하지 않는다. 정확한 expiresAt 제공이 없으면 “시간이 지나면 물품을 다시 인식해 주세요”를 사용한다.
- 완료 후 처음으로 버튼은 즉시 복귀한다. 저장 중/결과 불명확 시에는 완료 복귀 타이머·유휴 초기화를 적용하지 않는다.

| 오류 | 한 번에 원인과 다음 동작 한 가지를 우선 제시. 재연결 이벤트마다 같은 팝업을 중복 생성하지 않음. 잘못된 코드·태그·재고 충돌·저장 불명확을 구분 |
| 하단 동작 | 이전·취소는 보조, 다음/확정은 주 버튼. 저장 중에는 조작 잠금과 처리 중 문구. 완료는 처음으로만 주요 동작 |

큰 글씨/아이콘은 대비 3:1, 일반 본문은 4.5:1을 목표로 구현 후 확인한다. 키보드 포커스 표시, 화면 전환 제목 포커스, 오류 live 영역, 모달 내부 포커스 유지와 원래 버튼 복귀를 제공한다. 카운트다운을 매초 음성으로 반복하지 않는다. 확대·시스템 글자 크기 변경에서도 하단 버튼과 오류 안내가 잘리지 않게 한다. 소리·진동은 필수 피드백 수단이 아니며 추가 여부는 후속 결정이다.

### 공유 구현과 플랫폼 경계

공유 후보는 대여/반납 상태 모델, API 요청·응답 검증, 오류 매핑, 요청 중복 방지, 디자인 토큰·문구·화면 구성이다. 플랫폼 어댑터는 외장 리더기 이벤트·서버가 요구하는 proof, 앱 수명주기, 보안 저장, 전체 화면/종료, 업데이트를 담당한다. Windows exe와 Android 앱이 필요하다는 결정만 확정이며 Electron/Tauri/Capacitor/네이티브 등 패키징 기술을 이 문서로 선택하지 않는다.

3단계는 공통 화면·상태 개편과 Windows/태블릿 레이아웃 적용을 먼저 수행한다. 설치 패키징·네이티브 장치 어댑터·운영 모드는 별도 구현 단위로 추적한다. 웹 화면을 Android 크기로 표시한 것만으로 Android 설치 앱이나 외장 리더기 통합 완료로 보고하지 않는다. 관리자 종료·업데이트는 실제 호스트 기능이 연결되기 전에는 동작한다고 가장하지 않는다.

### 구현 순서와 검증 기준

1. 공통 토큰·연결 상태·대기 홈·두 화면 배치 및 숫자 키패드.
2. 대여 코드→종류→NFC→확인→저장→완료, 서버 dueAt 표시.
3. 반납 NFC→상태→코드→최종 확인 추가→저장→완료, 스캔 증명 만료와 재인식.
4. 취소·유휴 경고·앱 복귀·중복 스캔·불명확 결과 복구. 저장 중 자동 초기화 문제 수정.
5. 관리자 운영 진입과 호스트 기능 경계, 플랫폼 패키징 설계.
6. fixture 회귀·기기별 화면 검증 후 설치 앱·실제 서버/DB·외장 리더기 통합 검증을 각각 기록.

| 검증 영역 | 확인할 사례 |
|---|---|
| 대여 | 잘못된/만료/사용된 코드, grant 만료, 재고 없음·조회 실패, 종류 불일치, 같은 실물 중복 인식, 확정 시 재고 충돌, 서버 예정일 |
| 반납 | proof 없음·만료·잘못된 서명, 티켓 만료, 정상/손상 선택, 다른 대여자의 코드, 잘못된 코드 수정, 이미 반납된 물품, 최종 확인 전 저장 요청 0건 |
| 저장 복구 | 연타와 Enter 중복, 응답 유실·5xx·잘못된 성공 응답, 동일 요청 복구, 복구 중 새 키/코드 방지, 유휴 시간이 지나도 요청 문맥 보존 |
| 세션 | 취소·완료 후 정보 제거, 늦은 응답이 다음 사용자에 섞이지 않음, 뒤로가기·회전·백그라운드 복귀·절전 시 만료 재평가 |
| 화면 | Windows 1280×720·1366×768·1920×1080의 논리 가용 공간, 태블릿 가로/세로·안전 여백·시스템 배율. 정확한 실제 장치 가용 크기는 실행 시 확인 |
| 접근성 | 터치만으로 전체 흐름, 숫자키/Tab/Enter/Esc, 모달 포커스, 글자 확대·긴 이름·오류 문구, 감소된 동작 |
| 호스트 | 외장 리더기 분리·재연결·이벤트 중복, 종료 권한, 자동 실행·업데이트·재시작 시 미확인 처리 보존. 실제 앱별로 검증 |

현재 단계는 문서화만 수행했으며 이미지·제품 소스를 수정하거나 위 테스트를 실행하지 않았다. 기존 브리지 테스트 통과 기록은 Android 장치 검증으로 해석하지 않는다.
