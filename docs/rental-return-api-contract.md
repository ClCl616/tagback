# 물품 반납 API 계약

## NFC 스캔 확인

1. ACR1552U 리더기가 태그 UID를 읽고 Java 브리지가 `bridgeId`, `uid`, 발급 시각, 임의 nonce, HMAC-SHA256 서명을 포함한 스캔 증명을 만든다.
2. 브라우저는 이 증명을 `POST /api/v1/rentals/return/scan`에 전달한다. UID나 물품 번호만으로는 이 API를 호출해 유효한 스캔으로 인정받을 수 없다.
3. 서버는 브리지와 공유하는 `NFC_SCAN_SECRET`으로 서명을 검증하고, `bridgeId`가 서버의 `NFC_BRIDGE_ID`와 일치하는지, 발급 시각이 60초 이내인지 확인한다. 성공한 nonce는 스캔 교환 단계에서 즉시 기록해 증명 재전송을 막는다.
4. 서버는 서명된 UID로 활성 NFC 태그, 물품, 현재 대여 중인 대여 기록을 조회한다. 대상이 대여 중이면 키오스크 ID·UID·스캔 nonce·물품·대여 기록에 묶인 임의 UUID 티켓을 발급한다. 티켓 유효기간은 60초다.

요청 예시:

```json
{
  "proof": {
    "bridgeId": "kiosk-1",
    "uid": "04C8AB82492490",
    "issuedAt": 1790000000000,
    "nonce": "98f6da84-f149-4e1d-b6f5-370523b76d2b",
    "signature": "<HMAC-SHA256 hex>"
  }
}
```

응답에는 물품 정보와 `rentalId`, 서버 발급 `scanTicketId`가 포함된다. 브라우저가 보낸 물품 번호는 조회 기준으로 사용하지 않는다.

## 반납 확정

`POST /api/v1/rentals/return`은 서버 티켓, 해당 티켓을 발급받을 때 사용한 서명 스캔 증명, 사용자가 선택한 `condition`을 받는다. 이 증명은 서버가 티켓의 키오스크 ID·UID·nonce와 일치하는지 확인하는 데만 사용한다.

```json
{
  "scanTicketId": "6fa7b810-77bd-4f49-8cf9-e9bd457f1101",
  "proof": {
    "bridgeId": "kiosk-1",
    "uid": "04C8AB82492490",
    "issuedAt": 1790000000000,
    "nonce": "98f6da84-f149-4e1d-b6f5-370523b76d2b",
    "signature": "<HMAC-SHA256 hex>"
  },
  "condition": "NORMAL"
}
```

서버는 티켓의 만료·사용 여부와 현재 태그 및 대여 기록을 확인하고, 서명 증명의 키오스크 ID·UID·nonce가 티켓과 모두 같은지 대조한다. 티켓은 DB의 조건부 원자 업데이트로 한 번만 소비된다. 대여 ID와 물품 ID는 티켓에 저장된 값으로 확정되므로 브라우저가 다른 대여나 물품을 지정할 수 없다. 성공한 정상 반납은 물품을 `AVAILABLE`로, 손상 반납은 `INSPECTION`으로 변경하고 반납 이력 및 점검 접수를 저장한다.

티켓이 만료되거나 이미 소비되었거나 해당 대여 상태가 바뀌었으면 반납을 거절하고, 새 태그 인식을 요구한다. 브라우저는 스캔 증명과 HMAC 비밀값을 보관하지 않으며 최종 요청에는 증명 대신 짧은 수명의 서버 티켓만 보낸다.

## 배포 설정

NFC 브리지와 백엔드에 동일한 32바이트 이상의 임의 `NFC_SCAN_SECRET`을 환경 변수로 설정하고, 동일한 키오스크 식별자를 `NFC_BRIDGE_ID`로 지정한다. 백엔드는 설정된 단일 키오스크 ID만 신뢰한다. 프런트엔드에는 비밀값을 두지 않는다. 브리지 Mock UID 모드는 실제 리더기 서명을 만들지 않아 이 반납 경로를 통과하지 않는다.
