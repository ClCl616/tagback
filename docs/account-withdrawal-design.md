# 회원 탈퇴와 이력 보관

카카오 인증 프로필에서 `DELETE /api/v1/account`는 현재 세션과 Origin을 검사하고 탈퇴를 처리한다. `X-Expected-User-Id`에 화면에서 확인한 회원번호를 보내며, 현재 세션의 계정과 다르면 `409 ACCOUNT_CHANGED`로 거부한다. 이 값은 인증 수단이 아니라 계정 전환 방지용이다. 성공하면 204와 세션·브라우저 쿠키 삭제 헤더를 반환한다. 미반납 또는 연체 대여가 있으면 `409 OUTSTANDING_RENTALS`를 반환하고 데이터를 변경하지 않는다. `GET /api/v1/account/outstanding-rentals`는 사전 안내용이며 탈퇴 성공을 보장하지 않는다.

탈퇴는 트랜잭션 안에서 세션을 다시 확인하고 사용자 행을 잠근 뒤 미반납 대여를 재검사한다. 대여 코드 발급과 대여 확정도 사용자 행을 먼저 잠그므로, 대여가 먼저 완료되면 탈퇴가 거부되고 탈퇴가 먼저 완료되면 대여를 만들 수 없다. 실패하면 이력 이동과 계정 정리도 함께 롤백한다.

반납 완료 이력은 사용자 ID·기존 대여 ID·사용자별 대체 식별자 없이 `withdrawn_rental_history`에 저장한다. 물품 ID, 대여·예정·반납 날짜(UTC 날짜 단위), 반납 상태와 삭제 시각을 남긴다. 기존 대여 행과 관련 인증·재시도 기록을 삭제하고, 물품 상태 이력의 사용자 참조를 제거한다. 관리자 작업 이력에는 삭제된 사용자의 ID 대신 탈퇴한 작업자 표시만 남는다. 저장된 정보의 조합으로 식별될 가능성을 별도로 검토해야 하며, 이 처리를 완전한 익명화라고 단정하지 않는다.

삭제 시각은 탈퇴 시각으로부터 UTC 기준 달력상 1년 후다. 서버가 시작된 후 1분부터 기본 1시간 간격으로 만료된 보관 이력을 삭제한다. 서버 중단 중에는 실행되지 않으며 재시작 후 다음 작업에서 처리한다. 보관된 탈퇴 이력은 현재 관리자 화면이나 기존 관리자 대여 조회에 포함되지 않는다.

기존 세션·브라우저 등록과 카카오 연결을 삭제한다. 해당 식별값으로 재가입하면 새 계정으로 생성되며 이전 보관 이력과 연결되지 않는다. 이전 인증 결과와 로그인 응답 스냅샷도 정리한다. 삭제된 계정의 기존 토큰으로는 로그인할 수 없다. API 응답 유실 후 기존 세션이 삭제됐을 수 있으므로 별도의 탈퇴 결과 복구 API는 없다. 화면은 요청 결과를 알 수 없으면 완료로 표시하지 않고 재요청 대신 확인을 안내한다. 같은 탭의 sessionStorage에 미확정 표시를 유지하며 탭이나 저장소가 지워지면 이 표시는 복원되지 않는다.

2026-11-18 격리 PostgreSQL에서 개발·운영 인증 프로필의 탈퇴, 미반납·연체 거부, 대여와 탈퇴의 양방향 경합, 트랜잭션 롤백, 이전 세션·대여 토큰 무효화, 재가입과 보관 만료 경계를 검증했다. 이는 실제 카카오 채널이나 운영 DB 검증을 뜻하지 않는다.

2026-11-23 별도 임시 PostgreSQL과 실제 서버·브라우저의 사용자 탈퇴 화면 검사를 다시 통과했다. 같은 시험의 관리자 조회·본인 반납·대여 응답 유실 및 손상 반납을 포함해 4개가 통과했다. 카카오 스킬 및 NFC 입력은 시험용 대체이며, 실제 장비·운영 DB나 백업 복원 후 삭제 재적용 검증은 포함하지 않는다.

## 남은 운영 검증

- 백업 복원으로 탈퇴한 계정과 삭제 이력이 되살아나지 않도록, 운영 DB와 독립적인 삭제 기록 및 복원 전 재적용 절차를 설계하고 실제 백업으로 검증해야 한다.
- 보관 목적이 1년 전에 종료되는 경우의 수동 삭제 절차, 재식별 위험과 별도 법적 보존 필요성은 운영 전에 검토해야 한다.
- Flyway V23은 격리 DB와 기존 로컬 개발 DB에 적용했다. 다른 개발자 DB나 운영 환경에는 적용 전에 백업과 배포 순서를 확인한다. [기존 DB 전환 기록](kakao-existing-db-transition.md)
