## 1. 인증 정책 확정

> 이 단계의 체크는 **정책 결정 완료**를 뜻합니다. 실제 기능 구현은 4~6단계에서 별도로 확인합니다.
>
- [x]  회원가입은 프로필 입력 → 챗봇 인증 → PIN 설정 → 가입 완료로 진행한다.
- [x]  등록된 브라우저에서는 PIN으로 로그인한다.
- [x]  새 브라우저에서는 챗봇 인증 후 PIN을 입력한다.
- [x]  PIN 재설정에는 계정에 연결된 챗봇 인증을 사용한다.
- [x]  PIN 재설정 후 기존 세션과 브라우저 등록을 폐기한다.
- [x]  계정당 활성 브라우저는 1개로 유지한다.
- [x]  전화번호를 수집하지 않고 계정·로그인·키오스크 표시 방식을 변경한다.
- [x]  가입을 취소하거나 인증이 만료되면 기존 요청을 사용할 수 없게 한다.
- [x]  이미 가입된 챗봇 식별값이면 로그인 또는 PIN 재설정을 안내한다.
- [x]  미반납 물품이 있으면 탈퇴할 수 없도록 한다.
- [x]  탈퇴 후 같은 식별값으로 새 계정에 가입할 수 있도록 한다.
- [x]  반납 완료 이력은 탈퇴한 계정과 연결되지 않도록 처리하고, 1년간 보관 후 삭제한다.

## 8. 테스트

- [x]  같은 챗봇 식별값으로 중복 가입할 수 없다.
- [x]  만료된 코드는 사용할 수 없다.
- [ ]  이미 사용한 코드는 다시 사용할 수 없다.
    - 가입 완료에 사용된 인증 결과의 중복 소비는 차단한다. 같은 사용자의 스킬 재전송과 같은 요청의 멱등성 재시도는 허용한다.
- [x]  잘못된 코드를 반복 입력하면 제한이 적용된다.
- [x]  회원가입용 인증 결과를 PIN 재설정에 사용할 수 없다.
- [x]  인증을 시작하지 않은 다른 브라우저가 결과를 가져갈 수 없다.
- [ ]  위조된 스킬 요청으로 인증을 완료할 수 없다.

### 로그인과 복구

- [x]  등록된 브라우저에서 PIN으로 로그인할 수 있다.
- [x]  새 브라우저에서 챗봇 인증과 PIN으로 로그인할 수 있다.
    - 개발용 백엔드 통합 테스트에서 확인했다. 프론트엔드와 실제 카카오 대화를 연결한 종단 시험은 남아 있다.
- [ ]  PIN 실패 제한이 기존 정책대로 동작한다.
- [x]  연결된 챗봇 사용자로 PIN을 재설정할 수 있다.
- [x]  다른 챗봇 사용자로 기존 계정의 PIN을 재설정할 수 없다.
- [x]  PIN 재설정 후 이전 세션과 브라우저 등록이 무효화된다.
    - 위 세 항목은 개발용 백엔드 통합 테스트에서 확인했다. 실제 카카오 대화와 프론트엔드를 연결한 종단 시험은 남아 있다.

### 기존 기능 회귀

- [ ]  회원가입 후 사용자 웹과 내 대여 내역이 정상 동작한다.
- [ ]  키오스크 사용자 인증·대여·반납이 정상 동작한다.
- [ ]  관리자 사용자·대여 조회가 정상 동작한다.
- [x]  DB 마이그레이션 후 기존 데이터가 의도대로 유지된다.
    - 기존 버전 데이터가 있는 격리 시험 DB에서 확인했다. 프로젝트 기존 DB에는 아직 적용하지 않았다.
- [ ]  운영 설정에서 SMS mock 개발 API에 접근할 수 없다.
- [ ]  테스트용 카카오 채널과 실제 백엔드를 연결해 전체 흐름을 검증한다.
