# 카카오톡 챗봇 인증 정책

상태: 핵심 인증 정책 및 탈퇴 후 이력 보관 방침 확정. 세부 운영 값과 구현 검증은 남아 있다. 이 문서는 실제 구현이나 카카오 연동 완료를 뜻하지 않는다.

## 범위와 기준

- 가입·새 브라우저 로그인·PIN 재설정에 카카오톡 챗봇 인증을 사용한다.
- 카카오톡을 사용할 수 없는 사람과 카카오 계정을 잃어버린 경우의 복구는 이번 범위에서 제외한다.
- 1인 1계정을 목표로 하되, 중복 가입은 같은 봇의 챗봇 사용자 식별값을 기준으로 방지한다. 한 사람이 여러 카카오 계정을 사용하는 경우의 동일인 판별은 범위에서 제외한다.
- 챗봇 사용자 식별값의 제공 조건과 유지 범위는 실제 카카오 채널 설정 및 연동 테스트로 확인해야 한다.

## 인증 흐름

| 상황 | 정책 |
| --- | --- |
| 회원가입 | 프로필 입력 → 챗봇 인증 → PIN 설정·확인 → 계정 생성과 브라우저 등록 |
| 등록된 브라우저 로그인 | 유효한 브라우저 등록 확인 → PIN 검증 → 세션 발급 |
| 새 브라우저 로그인 | 챗봇 인증으로 연결된 계정 확인 → PIN 검증 → 브라우저 등록과 세션 발급 |
| PIN 재설정 | 기존 계정에 연결된 챗봇 인증 → 새 PIN 설정 → 기존 세션과 브라우저 등록 폐기 |
| 중복 가입 | 이미 연결된 식별값으로 신규 계정을 만들지 않고 로그인 또는 PIN 재설정을 안내 |

가입, 로그인, PIN 재설정의 인증 결과는 목적별로 구분한다. PIN 입력 제한, 쿠키와 세션 만료 정책은 별도 변경 결정 전까지 현재 서버 정책을 기준으로 한다. 서버는 인증 결과를 최종 작업에서 다시 검증하고 한 번만 소비한다.

## 브라우저 및 연락처

- 활성 브라우저 등록은 계정당 1개로 유지한다.
- 새 브라우저에서 챗봇 인증과 PIN 검증이 모두 성공하면 이전 브라우저 등록과 세션을 폐기하고 새 브라우저를 등록한다. 실패하거나 취소하면 이전 등록과 세션을 유지한다.
- 일반 로그아웃은 세션을 종료하고 브라우저 등록은 유지한다.
- 전화번호를 수집하지 않는다. 계정·로그인 응답에는 전화번호를 포함하지 않고, 키오스크에는 이름과 회원번호를 표시해 동명이인을 구분한다. 이름이 없는 기존 계정은 `회원`과 회원번호로 표시한다.

## 취소·만료 및 재시도

- 계정은 가입을 최종 완료할 때 생성한다. 챗봇 인증 성공만으로 계정을 만들지 않는다.
- 사용자가 가입을 취소하면 해당 인증 요청을 폐기하고, 다시 시작할 때 새 요청을 발급한다. 브라우저 종료 등 취소 통지가 불가능한 경우 남은 요청은 만료 시 사용할 수 없게 한다.
- 인증 요청이 만료되면 새 요청을 발급받는다. 챗봇 인증 후 PIN 설정 중 인증 결과가 만료되어도 다시 인증한다.
- 사용한 코드는 재사용할 수 없다. 새로 발급할 때 같은 브라우저의 이전 미완료 요청은 무효화한다.
- 요청 결과를 받지 못한 경우 임의로 가입 성공이나 실패로 간주하지 않는다. 최종 작업의 중복 실행을 방지하는 재시도와 상태 확인 방법은 API 설계에서 정한다.
- 코드 유효시간, 시도 횟수, 발급 제한은 구현 전에 정하고 서버가 강제한다.

## 탈퇴와 재가입

- 반납하지 않은 대여가 있으면 회원 탈퇴를 허용하지 않는다. 연체 중인 대여도 반납되지 않았다면 탈퇴할 수 없다.
- 모든 물품을 반납하면 탈퇴할 수 있으며, 탈퇴 후 같은 챗봇 식별값으로 재가입할 수 있다.
- 탈퇴가 완료되면 기존 로그인 세션과 브라우저 등록을 폐기한다. 재가입은 새로운 계정으로 처리한다.
- 탈퇴 시 카카오 챗봇 식별값과 기존 계정의 연결을 제거해 같은 식별값으로 재가입할 수 있게 한다.
- 반납 완료된 이력은 탈퇴일부터 1년간 운영에 필요한 범위에서 보관한 뒤 삭제한다. 1년은 팀의 운영상 결정이며 법정 의무기간을 뜻하지 않는다.
- 탈퇴 시 이름·직업·카카오 식별값·기존 user ID와 대여 이력의 연결을 제거한다. 사용자별 고정 대체 ID나 식별값 해시로 과거 이력을 재연결하지 않는다.
- 필요한 물품 및 대여·반납 날짜를 남기되 시각은 날짜 단위로 축소한다. 물품, 날짜, 장소 등과 다른 자료의 결합으로 개인을 알아볼 위험을 검토하고, 위험이 남으면 항목을 더 줄이거나 집계한다. 단순히 이름이나 ID를 가린 것만으로 익명화가 완료됐다고 단정하지 않는다.
- 재가입은 새 계정으로 처리하며 탈퇴 전 이력을 새 계정에 연결하지 않는다.
- 보관 기간이 끝나거나 그 전에 보관 목적이 없어지면 지체 없이 삭제한다. 다른 법령에 따른 보존이 필요한 정보는 적용 여부·범위·기간을 확인해 분리 관리한다.
- 운영 DB 외 로그·백업·내보내기 파일에도 식별정보가 남을 수 있으므로 접근과 보존 주기를 관리하고, 백업 복원 시 탈퇴·삭제 조치가 되살아나지 않도록 재적용한다. 구체적인 백업 만료 주기는 운영 설계에서 정한다.
- 백엔드 탈퇴 API는 완료된 대여 이력을 계정과 분리해 보관하고 정리한다. 사용자 화면, 백업 복원 시 삭제 재적용 및 운영 환경 검증은 남아 있다. 자세한 내용은 [회원 탈퇴와 이력 보관](account-withdrawal-design.md)을 참고한다.

## 추가로 결정할 사항

- 기존 데이터가 보존 대상이라면 이미 인증된 사용자와 챗봇 식별값을 안전하게 연결하는 전환 절차를 설계한다.
- 인증 코드 유효시간과 발급·시도 제한을 확정한다.
- 위 이력 처리 방침을 현재 대여 이력의 사용자 외래 키와 관리자 조회에 맞춰 구현하고, 비식별화·삭제·백업 복원 시 재적용을 검증한다.

법령상 별도 보존 의무의 적용 여부와 이용자에게 필요한 고지는 실제 운영 조건에 맞춰 확인한다.
