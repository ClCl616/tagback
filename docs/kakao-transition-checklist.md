# TagBack 카카오 챗봇 인증 전환 체크리스트

> **목표:** 최종 사용자 인증에서 전화번호와 SMS를 제거하고 카카오 챗봇 인증과 PIN을 사용한다. 등록된 브라우저는 PIN으로 로그인하고, 새 브라우저 로그인과 PIN 재설정에는 연결된 챗봇 인증을 사용한다.
>
> **범위:** 1인 1계정을 목표로 하되, 중복 가입은 같은 봇의 챗봇 사용자 식별값을 기준으로 방지한다. 한 사람이 여러 카카오 계정을 사용하는 경우의 동일인 판별은 범위에서 제외한다. 카카오톡 이용을 전제로 하며 카카오 계정 상실 시 별도 복구도 이번 범위에서 제외한다.
>
> **표시 기준:** 완료 표시는 해당 항목에 적힌 범위의 구현 또는 검증 완료를 뜻한다. 격리 시험 완료는 실제 카카오톡이나 운영 환경 시험 완료를 뜻하지 않는다. 1단계는 정책 결정만 뜻한다.
>
> **갱신 기준:** 2026-11-19 작업 트리, 저장된 테스트 결과 및 실제 카카오톡 시험 기록을 대조했다. 작업 트리에는 아직 커밋되지 않은 변경이 포함되어 있다.

- [x] 새 브라우저에서는 챗봇 인증 후 기존 PIN을 입력한다.
- [x] PIN 재설정에는 계정에 연결된 챗봇 인증을 사용하고 기존 세션과 브라우저 등록을 폐기한다.

- [x] 1인 1계정을 목표로 하고, 중복 가입 방지는 같은 봇의 챗봇 식별값을 기준으로 한다. 여러 카카오 계정을 사용하는 동일인 판별은 제외한다.
- [x] 전화번호를 수집하지 않으며 최종 사용자 인증에서 SMS를 제거한다.

  - `VITE_KAKAO_CHANNEL_URL`이 설정되지 않으면 버튼 대신 채널을 직접 열도록 안내한다.
- [x] 돌아온 사용자의 인증 상태를 확인하고 성공·만료·취소·중복 가입·연결 실패·재시도를 안내한다.
- [x] 등록 브라우저 PIN 로그인은 유지하고, 새 브라우저 로그인에 챗봇 인증과 PIN 입력을 연결한다.
- [x] PIN 재설정 화면에서 SMS 대신 연결된 챗봇 인증을 사용한다.
- [x] 계정 화면에서 전화번호를 표시하지 않는다.
- [x] 로그인·세션·브라우저 상태 응답과 프론트엔드 계약에서 전화번호 필드를 제거한다.
- [x] 키오스크 대여자 확인에 이름과 회원번호를 함께 표시한다. 이름이 없는 기존 계정은 `회원`과 회원번호를 표시한다.
  - 서버·프론트엔드·Windows 호스트의 대여 인증 응답 계약을 함께 변경했다. 구버전과 호환되지 않으므로 함께 배포해야 한다.
- [x] 변경된 계약으로 실제 서버·격리 DB·브라우저와 Windows 호스트 통신 모듈을 연결해 가입·등록 브라우저 로그인·대여·반납을 검증한다.
  - 2026-11-18 백엔드 전체 347개와 실제 서버·격리 DB를 사용하는 브라우저 테스트 3개가 통과했다. 세션에 전화번호 필드가 없고, 대여 인증의 이름·회원번호가 Windows 호스트 통신 모듈과 키오스크 확인 화면에 전달되는 것을 확인했다. 카카오 스킬과 NFC 입력은 시험용이며 Windows 설치 앱 자체는 실행하지 않았다.
  - 웹·키오스크 빌드, 프론트 단위 43개, HTTP fixture 브라우저 31개, 키오스크 fixture 브라우저 17개와 Windows 호스트 단위 9개도 통과했다.
- [ ] 변경된 계약을 반영해 Windows 설치 앱을 다시 빌드하고 실제 앱·키오스크 장비에서 통합 검증한다.
- [x] 인증 화면 문구를 카카오톡 연결·가입 인증에 맞춘다.

## 8. SMS 제거와 탈퇴 기능

- [x] SMS mock API·서비스·개발 설정 및 SMS 전용 테스트를 제거하고 카카오 인증 테스트로 전환한다.
- [x] 전화번호 로그인·SMS 인증·전화번호 변경 경로와 인증 화면을 제거하거나 새 방식으로 교체한다.
- [x] 전화번호가 남아 있는 세션 응답 계약과 키오스크 표시를 7단계에서 정리한다.
- [x] 공통 인증·대여 기능과 새로운 테스트가 SMS 코드·비밀값에 의존하지 않는지 확인한다.
- [ ] 기존 개발 데이터 초기화와 스키마 정리는 4단계의 결정 및 별도 실행에 따라 처리한다.
- [x] 미반납 물품이 있으면 탈퇴를 거부하고 대여 확정과의 동시성을 제어한다.
- [x] 탈퇴 후 동일 챗봇 식별값으로 재가입할 수 있도록 구현한다.
- [x] 반납 완료 이력을 계정과 분리하고 탈퇴 후 1년 보관·삭제하도록 구현한다.
  - 백엔드 API와 격리 PostgreSQL에서 확인한 범위다. 보관 이력은 현재 관리자 조회에 포함되지 않는다. 상세는 [탈퇴 구현](account-withdrawal-design.md)을 참고한다.
- [x] 사용자 탈퇴 화면에 미반납 안내·명시적 확인·결과 불명 안내를 연결한다.
  - 계정 전환 시 서버가 요청을 거부하며, 실제 서버·격리 DB에서 화면을 통한 탈퇴를 시험했다. 실제 카카오 채널과 운영 환경 검증은 별도다.
- [ ] 백업 복원 시에도 삭제가 재적용되는 방식을 정하고 검증한다.
- [ ] 보관 이력의 재식별 위험과 별도 법적 보존 필요성, 보관 목적이 조기 종료될 때의 삭제 절차를 검토한다.
- [ ] 보관된 탈퇴 이력의 관리자 조회 필요 여부와 결과가 불명확한 탈퇴 요청의 담당자 확인 절차를 정한다.

## 9. 최종 통합·운영 전 검증

- [x] 개발용 백엔드에서 같은 식별값 중복 가입, 만료, 요청 제한과 다른 브라우저의 결과 접근을 검증한다.
- [x] 개발용 백엔드에서 목적 혼용, 중복 소비, 응답 유실 재시도와 PIN 실패 제한을 검증한다.
- [x] 개발용 백엔드에서 연결된 계정의 PIN 재설정, 다른 계정 보호와 이전 세션·브라우저 폐기를 검증한다.
- [ ] 위조·누락·중복 스킬 비밀 헤더와 요청 재생 방어를 운영 구성과 실제 프록시 경계에서 검증한다.
- [x] 로컬 시험 웹·격리 DB와 실제 카카오톡으로 회원가입·PIN 재설정·등록 폐기 후 챗봇 인증과 새 PIN 로그인을 시험한다.
  - 2026-11-19 같은 브라우저에서 확인했다. 운영 환경 검증은 아니다.
- [ ] 별도 브라우저 또는 기기에서 실제 카카오톡 인증과 PIN으로 로그인한다.
- [ ] 실제 카카오톡을 사용하는 화면에서 인증 취소·만료·재시도를 종단 시험한다.
- [x] 격리된 DB와 백엔드에서 전화번호 없는 사용자의 인증·대여·반납을 회귀 테스트한다.
- [x] 격리된 백엔드·DB와 브라우저에서 모의 스킬·NFC 증명으로 대여·반납과 관리자 조회를 시험한다.
- [ ] 실제 카카오 연결과 키오스크 장비를 포함해 전화번호 없는 사용자의 사용자 웹·대여 내역·인증·대여·반납·관리자 조회를 종단 시험한다.
- [ ] 최종 운영 설정에서 SMS 및 개발용 API가 노출되지 않음을 확인한다.
- [x] 격리 DB에서 탈퇴 제한·동시 대여·재가입·이력 분리 및 보관·삭제를 검증한다.
- [ ] 최종 운영 환경에서 탈퇴 및 복원 후 삭제 재적용을 검증한다.
- [ ] 운영 DB·비밀·Origin·HTTPS·로그·응답 시간과 채널 담당자 준비를 확인한 후 전환한다.
