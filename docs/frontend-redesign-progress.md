# TagBack 리디자인 진행 보고서

기준일: 2026-11-06 (한국 시간). 작업 브랜치: `codex/user-web-redesign`, 구현 시작 기준 커밋: `3556af4`.

구현 및 테스트 스크립트 커밋: `4690e0e` (`feat: redesign user admin and kiosk flows with regression coverage`). 아래 커밋 전 검증은 이 구현 내용에 대해 수행했으며 마지막 정리는 테스트 파일 끝의 불필요한 빈 줄 제거뿐이다.

사용자 웹·관리자 웹·키오스크 공통 UI를 기존 실제 HTTP API에 연결한 상태로 리디자인했다. 키오스크의 실제 로컬 서버·PostgreSQL 검증까지 진행했으며 Windows·Android 설치 앱과 실물 장치 검증은 남아 있다. 이 보고서와 함께 저장되는 구현은 작업 브랜치 결과이며 develop/main 병합이나 운영 배포 완료를 의미하지 않는다.

## 확정된 운영 구조와 사용 흐름

| 영역 | 대상 | 책임 |
|---|---|---|
| 사용자 웹 | 휴대폰·PC 브라우저, 설치 불필요 | 가입·로그인·물품/재고·이용 코드·본인 대여/이력 |
| 관리자 웹 | 일반 사용자 메뉴에 없는 별도 관리 주소 | ADMIN 인증, 물품 CRUD·태그 연결·상태·사용자/대여/연체 조회 |
| 키오스크 앱 | Windows PC 설치형 및 Galaxy Tab S10+ Android 앱 | 외장 NFC 실물 식별, 본인 코드 확인, 대여·반납 확정 |

세 영역은 공통 서버·DB와 계정 체계를 사용한다. 주소 비공개는 노출 정책이며 실제 권한 검사는 서버가 수행한다. 사용자 웹과 관리자 웹에서는 대여·반납을 확정하지 않는다.

- 대여: 사용자 웹 코드 발급 → 키오스크 코드 → 종류 선택 → NFC → 최종 확인 → 서버 저장 성공 → 완료.
- 반납: 키오스크 NFC → 정상/손상 선택 → 본인 코드 → 최종 확인 → 서버 저장 성공 → 완료.
- 관리: 물품 등록·태그 연결·상태 변경 및 이용 현황 조회.
- 기존 6자리 코드·인증·태그·멱등 재시도 계약을 유지한다. 예시 이미지의 QR·영문 코드·수량·연락처를 운영 계약이나 데이터로 사용하지 않는다.

## 설계와 구현 이력

| 순서 | 결과 |
|---|---|
| 1 | 기존 기능 유지, 디자인·사용 흐름 전면 개편과 3개 운영 영역 확정 |
| 2 | 사용자 모바일·PC, 관리자 대시보드, 키오스크의 파랑/흰색 레퍼런스 4개 검토 |
| 3 | 사용자 웹 흐름 시안 4장과 상태 보충 시안, 화면·상태 및 디자인 규칙 작성; 기본 시안 승인 |
| 4 | 사용자 웹 로컬 구현 및 fixture 회귀. 전체 실제 통합 검증은 사용자 요청으로 보류 |
| 5 | 관리자 시안 4장, 화면·상태 및 디자인 규칙, 로컬 구현·fixture 회귀 |
| 6 | 키오스크 목표를 Windows와 Android 두 설치 앱으로 확장. 외장 리더기 지원 여부 재조사는 생략하기로 결정 |
| 7 | 키오스크 시안 5장, K01~K20 상태·시간·플랫폼 규칙, 공통 UI와 복구 구현 |
| 8 | 실물 장치 사용 불가로 로컬 서버·DB 검증부터 수행. 실제 SMS·NFC 및 설치 앱 검증은 미완료 |
| 9 | 구현·설계·검증·남은 작업을 저장소 문서와 작업 브랜치 커밋으로 정리 |

시안은 로컬 참고 자료로 유지한다. 화면과 세부 디자인 명세는 [리디자인 명세](frontend-redesign-design.md), 실행·경로·테스트는 [프론트엔드 안내](../frontend/README.md)를 참고한다. 과거 명세의 미착수 표기는 당시 기록이며 아래 최신 상태가 우선한다.

## 구현된 사용자 웹

- `UserWeb.tsx`와 범위를 제한한 `user-web.css`, 기존 `AuthFlow.tsx`를 사용한다. 모바일 하단 메뉴와 PC 사이드바를 제공한다.
- 비회원/회원 홈, 물품 검색·필터·재고·상세, 가입·SMS·PIN·로그인·재설정, 이용 코드, 본인 대여·상세·이용 이력·내 정보를 구현했다.
- 보호 화면은 로그인 후 원래 화면으로 복귀한다. 목록/상세 탐색과 이력 검색·반납 월 필터를 제공한다.
- 이용 코드는 사용자 클릭으로만 발급한다. 홈과 코드 화면이 같은 세션의 응답을 공유하며 화면 이동·포커스·만료로 자동 재발급하지 않는다.
- 로그아웃·계정 변경 시 코드와 개인 상태를 초기화하고 늦은 응답의 혼입을 방지한다. 소비 여부 조회 API가 없어 사용 완료를 추정하지 않는다.
- 서버 사진 계약이 없어 물품 아이콘을 사용한다. 웹 예약, QR, 공지, 알림, 관리자 링크를 추가하지 않았다.

## 구현된 관리자 웹

- `AdminWeb.tsx`, `AdminActions.tsx`, `admin-web.css`로 화면·작업·스타일을 분리했다.
- 현황, 물품 목록·상세·등록·수정·삭제·상태 변경, 태그 조회·연결, 대여·연체·이력·사용자 조회와 상세를 제공한다.
- 관리자 로그인·PIN 복구는 공통 인증을 재사용한다. ADMIN 확인 전 데이터 요청을 막고 세션 만료·권한 상실·계정 변경 시 데이터·상세·초안을 제거한다.
- 목록 검색·필터·페이지·선택 ID·사용자 조건은 URL 쿼리에 보존한다. 사용자 관련 이력은 이름이 아닌 ID로 연결한다.
- 전체 페이지 응답을 검증해 검색·현황을 계산한다. 현재 최대 10,000건 계약을 유지하며 초과·부분 응답을 전체 데이터로 표시하지 않는다.
- 물품 생성 후 태그 실패는 생성 ID를 유지해 태그만 재시도한다. 생성 결과 불명확 시 자동 재생성하지 않는다. 수정·상태·삭제·태그는 현재 정보 확인 경로를 제공한다.
- 모바일 카드/단독 상세와 PC 표/패널, 모달 포커스·Tab 순환·Esc·닫기 후 복귀를 적용했다.
- 주간 증감·추이 차트, 반납 당시 정상/손상 표시, 태그 교체/해제, 강제 반납, 권한 편집, 독촉·제재는 구현 범위에서 제외했다.

## 구현된 키오스크 공통 UI

- Windows 가로 배치와 태블릿 가로/세로 터치 배치를 제공한다. 공통 UI 구현은 설치 앱 완성을 의미하지 않는다.
- 대기·코드·종류·NFC·상태 선택·최종 확인·저장·완료 및 오류 복구를 구현했다. 반납 코드 입력만으로 저장하지 않으며 정상/손상은 최초 미선택이다.
- 키패드는 지우기·0·확인, 숫자키·Enter·뒤로가기·취소 확인·Esc를 지원한다.
- 일반 유휴 180초, 만료 전 경고 20초, 완료 후 12초 자동 복귀를 적용했다. 저장 중과 결과 불명확 상태에서는 취소·이전·자동 초기화로 요청 문맥을 지우지 않는다.
- 대여는 동일 grant·멱등키·본문, 반납은 동일 ticket·proof·상태·코드로 복구한다. 반납 API에 새 멱등 헤더를 추가하지 않았다.
- 명확한 코드 거부는 수정 가능하게 하고, 만료 인식은 재인식을 안내한다. 불명확 결과 뒤 인증/인식 만료는 실패로 단정하지 않고 관리자 확인 상태를 유지한다.
- 리더기를 한 번 구독하고 단계 외 입력·중복 스캔을 억제한다. 앱 복귀 시 연결과 만료를 재평가한다.
- 종류 API에 없는 재고 수량은 추정하지 않는다. 최종 예정일은 서버 dueAt만 표시한다.
- `platform.ts`의 `window.tagbackKioskHost` v1은 reader와 선택적 뒤로가기·운영 패널·종료 인터페이스다. Windows 기본 리더기는 기존 SSE 브리지이며 Android 네이티브 어댑터가 없으면 연결 안 됨으로 표시한다.
- 메모리 문맥 보존과 종료 경고는 강제 종료 후 복구를 보장하지 않는다. 호스트의 실제 ADMIN 인증·종료·자동 실행·업데이트는 후속 구현이다.

## 검증 기록과 한계

### 기존 작업에서 기록한 검증

| 범위 | 기록 | 한계 |
|---|---|---|
| 사용자 웹 HTTP fixture | 당시 28개 통과 | 실제 서비스 연결 검증 아님; 후속 전체 회귀에 포함 |
| 관리자 포함 HTTP fixture | 36개 통과 | 응답 fixture·장애 주입 사용 |
| 키오스크 브리지 브라우저 | 17개 통과, 이후 아이콘 수정 후 정상/손상 2개 추가 확인 | 가상 리더기 이벤트 사용; 서로 다른 실행 개수를 합산하지 않음 |
| 화면 | 사용자 320~1440px, 관리자 320/390/768/1024/1440px, 키오스크 1280×720·1366×768·1920×1080·1280×800·800×1280 | 브라우저 크기 검증; 실물 시스템 배율·태블릿 검증 아님 |
| 접근성 | 모달 포커스·Tab·Esc, 긴 이름, 관리자 CSS 2배 확대·감소된 동작 | 모든 브라우저의 실제 확대 메뉴 검증을 대체하지 않음 |
| 실제 로컬 서버·PostgreSQL | 10개 클래스, 65개 테스트, 실패/오류/skipped 0 | 서비스 단위 테스트도 포함; 전체 백엔드 테스트 수가 아님 |
| 실제 HTTPS 브라우저·DB | 2개 통과 | sms-mock 및 테스트가 공급한 서명 NFC 이벤트 |
| Java NFC 브리지 | 6개 클래스, 15개 통과, skipped 0 | 실물 리더기 검증 아님 |

실제 DB 검증은 대여 확정 전 미저장, 응답 유실 후 동일 요청 복구와 대여 1건 유지, 다른 대여자의 반납 코드 거부, 정상 반납 AVAILABLE·손상 반납 INSPECTION, 반납/상태 이력 중복 방지, 잘못된 HMAC 서명 거부를 확인했다. 실제 API·DB 성공 응답을 fixture로 대체하지 않았으며 응답 유실은 서버 처리 후 브라우저 응답을 끊어 재현했다.

재현 스크립트는 `backend/scripts/test-kiosk-live.ps1`이다. 별도 PostgreSQL 17 컨테이너와 loopback DB 55442/API 18082/HTTPS 5182를 사용한다. 종료 시 시작한 프로세스·컨테이너를 중지하고 진단 DB·로그는 보존한다. 테스트 인증서는 OS 신뢰 저장소에 설치하지 않는다. 실물 통합 검증 보류와 실제 서버·DB 검증 완료를 구분한다.

### 이번 커밋 전 확인

- `pnpm build`: 통과.
- `pnpm test`: 4개 파일, 31개 테스트 통과.
- `pnpm test:e2e`: 사용자·관리자·인증 HTTP fixture 브라우저 테스트 36개 통과.
- `pnpm exec playwright test -c playwright.bridge.config.ts`: 키오스크 브라우저 테스트 17개 통과.
- 실제 서버·DB·SMS·NFC 테스트는 이번 문서화 작업에서 재실행하지 않았다. 위 결과는 기존 실행 기록이다.
