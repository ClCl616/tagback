## 2026-11-18 임시 인증코드 콘솔 발송

카카오톡 챗봇 구현 전까지 `sms-mock` 인증코드를 API 콘솔에서 확인하도록 변경했다. `MockSmsDelivery`가 DB 커밋 후 전화번호 끝 4자리·요청 용도·6자리 코드·만료 시각·요청 ID를 출력한다. 기존 mock 수신함과 인증 API, 만료·재발송 제한을 유지한다. 롤백된 요청은 출력하지 않는다. 실행 안내는 [Compose 안내](../deploy/compose/README.md)의 임시 인증코드 절을 참고한다. 실제 SMS/챗봇 발송 또는 운영 배포 완료를 뜻하지 않는다.

## 2026-11-13 Docker Compose 구성

작업 분리: `codex/docker-compose` 브랜치에서 관리한다. 기존 개발 런처 브랜치의 Compose 파일·배포 정책 문서를 별도 작업 폴더로 옮겼으며 기준 커밋은 `652b4b7`이다. 이동 시 파일 동일성과 Compose 구성 검사를 확인했다. 기존 실행 검증은 아래 기록을 유지하며 이동 후 전체 기동 검사를 반복하지 않았다.

확정한 서버 배포 방향의 첫 구현으로 루트 `compose.yaml`과 `deploy/compose/`를 추가했다. 웹(Nginx HTTPS)·Spring Boot API·PostgreSQL 17을 함께 실행한다. 실행 및 설정 방법은 [Compose 안내](../deploy/compose/README.md)를 따른다.

- Java/Gradle 및 Node/pnpm 빌드는 Docker 내부에서 수행한다. 실행 API는 비루트 사용자로 동작한다. 기존 제품 소스·Windows 개발 런처는 변경하지 않았다.
- DB와 API 포트는 호스트에 공개하지 않고 웹 HTTPS만 loopback에 공개한다. DB/API healthcheck를 기다려 시작하며 PostgreSQL 데이터는 영구 볼륨에 보존한다.
- 초기화 스크립트는 임의 비밀값과 자체 서명 로컬 인증서를 생성하고 기존 값을 보존한다. Compose secrets와 Spring config tree를 사용한다. 비밀·인증서는 Git 및 이미지 빌드에서 제외하고 OS 신뢰 저장소는 변경하지 않는다.
- 현재 서버의 인증·대여 API는 `sms-mock & !prod & !production` 프로필에 묶여 있으므로 이번 기본 구성은 로컬 검증용이다. 외부 운영 공개 전 실제 SMS/운영 인증, 도메인·인증서·비밀값·백업·이미지 레지스트리 배포를 별도로 구현/검증해야 한다. production 프로필만 바꾸는 방식으로 운영 전환을 완료할 수 없다.
- 키오스크 앱은 기존 확정대로 GitHub Releases 수동 설치·업데이트이며 이 Compose에 앱이나 실물 리더기를 넣지 않는다. Android 보류 유지.

검증: Compose 구성 검사, PowerShell 구문 검사, 초기화 재실행 시 비밀 보존, 웹·API Docker 빌드 성공. 별도 `tagback-compose-check` 프로젝트와 HTTPS 18443에서 실제 PostgreSQL 및 Flyway 마이그레이션 20개 적용, 3개 서비스 healthy, SPA 경로·빌드 JS·API health/공개 카탈로그, 미인증 401, Secure 쿠키, 잘못된 Origin 403 확인. DB 컨테이너 재생성 전후 cluster ID가 같아 영구 볼륨 보존을 확인했다. 전체 업무 회귀·실제 SMS·실물 NFC·외부 운영 배포를 이번 검사 범위로 해석하지 않는다. 커밋·푸시·Release 게시를 수행하지 않았다.

API 컨테이너 재생성 후에도 같은 HTTPS 검사가 재통과했고 비루트 UID 10001을 확인했다. 검증용 컨테이너는 종료했으며 이미지·DB 볼륨은 보존했다. 기본 `tagback` 프로젝트는 시작하지 않았다.

## 2026-11-13 확정 배포 및 업데이트 정책

사용자 결정: 공통 서버는 Docker Compose로 실행하고, 키오스크 앱은 GitHub Releases에서 내려받아 수동 설치·업데이트한다. 이 결정은 배포 방식의 확정이며 Compose 구성 구현이나 Release 게시 완료를 의미하지 않는다.

| 대상 | 확정 방식 |
|---|---|
| 공통 서버 | 웹·백엔드·PostgreSQL을 Docker Compose 프로젝트로 함께 실행·관리한다. 컨테이너 하나에 모든 서비스를 넣는 방식으로 제한하지 않는다. |
| 사용자·관리자 웹 | 브라우저로 공통 서버에 접속한다. 웹 변경은 서버 배포로 반영한다. |
| Windows 키오스크 | 버전별 설치 파일을 GitHub Releases에 게시하고 운영자가 내려받아 수동 설치·업데이트한다. |
| Android 키오스크 | 개발 재개 후 APK를 GitHub Releases에서 수동 설치·업데이트한다. 기존 Android 구현 보류 결정은 유지한다. |
| 앱 자동 업데이트 | 현재 구현 범위에서 제외한다. 앱 자동 다운로드·자동 설치를 필수 작업으로 두지 않는다. |

키오스크 앱과 외장 NFC 연결은 각 현장 장치에서 실행하며 공통 서버 주소에 연결한다. 서버 업데이트는 이미지 버전과 Compose 설정으로 관리한다. DB는 영구 볼륨에 보존하며 백업·복구 절차는 별도로 마련한다.

후속 작업은 Compose 개발/운영 구성과 HTTPS·비밀값·DB 저장 설정, 이미지 빌드·배포 절차, GitHub Releases 버전·설치 파일·변경 내역·설치 안내, 수동 업데이트 시 앱 설정 유지와 진행 중/미확인 거래 보호, 서버·앱 버전 호환성 및 복구 절차다. 이미지 저장소·운영 주소·서명 방식·세부 컨테이너 구성은 별도 설계한다. 자동 실행·관리자 종료·연결 복구는 앱 자동 업데이트와 별개로 기존 후속 범위를 유지한다.

이 절이 이전 기록의 업데이트 방식 미정 또는 자동 업데이트 계획보다 우선한다. 이번 변경은 문서만 수정하며 코드·설정·실행 환경 변경, 커밋·푸시·Release 게시·배포는 수행하지 않는다.

## 확정된 운영 구조와 사용 흐름

| 영역 | 대상 | 책임 |
|---|---|---|
| 사용자 웹 | 휴대폰·PC 브라우저, 설치 불필요 | 가입·로그인·물품/재고·이용 코드·본인 대여/이력 |
| 관리자 웹 | 일반 사용자 메뉴에 없는 별도 관리 주소 | ADMIN 인증, 물품 CRUD·태그 연결·상태·사용자/대여/연체 조회 |
| 키오스크 앱 | Windows PC 설치형 및 Galaxy Tab S10+ Android 앱 | 외장 NFC 실물 식별, 본인 코드 확인, 대여·반납 확정 |

세 영역은 공통 서버·DB와 계정 체계를 사용한다. 주소 비공개는 노출 정책이며 실제 권한 검사는 서버가 수행한다. 사용자 웹과 관리자 웹에서는 대여·반납을 확정하지 않는다.

- 대여: 사용자 웹 코드 발급 → 키오스크 코드 → 종류 선택 → NFC → 최종 확인 → 서버 저장 성공 → 완료.
- 반납: 키오스크 NFC → 정상/손상 선택 → 본인 코드 → 최종 확인 → 서버 저장 성공 → 완료.
- 관리: 물품 등록·태그 연결·상태 변경 및 이용 현황 조회.
- 기존 6자리 코드·인증·태그·멱등 재시도 계약을 유지한다. 예시 이미지의 QR·영문 코드·수량·연락처를 운영 계약이나 데이터로 사용하지 않는다.

## 구현된 사용자 웹

- `UserWeb.tsx`와 범위를 제한한 `user-web.css`, 기존 `AuthFlow.tsx`를 사용한다. 모바일 하단 메뉴와 PC 사이드바를 제공한다.
- 비회원/회원 홈, 물품 검색·필터·재고·상세, 가입·SMS·PIN·로그인·재설정, 이용 코드, 본인 대여·상세·이용 이력·내 정보를 구현했다.
- 보호 화면은 로그인 후 원래 화면으로 복귀한다. 목록/상세 탐색과 이력 검색·반납 월 필터를 제공한다.
- 이용 코드는 사용자 클릭으로만 발급한다. 홈과 코드 화면이 같은 세션의 응답을 공유하며 화면 이동·포커스·만료로 자동 재발급하지 않는다.
- 로그아웃·계정 변경 시 코드와 개인 상태를 초기화하고 늦은 응답의 혼입을 방지한다. 소비 여부 조회 API가 없어 사용 완료를 추정하지 않는다.
- 서버 사진 계약이 없어 물품 아이콘을 사용한다. 웹 예약, QR, 공지, 알림, 관리자 링크를 추가하지 않았다.

## 구현된 관리자 웹

- `AdminWeb.tsx`, `AdminActions.tsx`, `admin-web.css`로 화면·작업·스타일을 분리했다.
- 현황, 물품 목록·상세·등록·수정·삭제·상태 변경, 태그 조회·연결, 대여·연체·이력·사용자 조회와 상세를 제공한다.
- 관리자 로그인·PIN 복구는 공통 인증을 재사용한다. ADMIN 확인 전 데이터 요청을 막고 세션 만료·권한 상실·계정 변경 시 데이터·상세·초안을 제거한다.
- 목록 검색·필터·페이지·선택 ID·사용자 조건은 URL 쿼리에 보존한다. 사용자 관련 이력은 이름이 아닌 ID로 연결한다.
- 전체 페이지 응답을 검증해 검색·현황을 계산한다. 현재 최대 10,000건 계약을 유지하며 초과·부분 응답을 전체 데이터로 표시하지 않는다.
- 물품 생성 후 태그 실패는 생성 ID를 유지해 태그만 재시도한다. 생성 결과 불명확 시 자동 재생성하지 않는다. 수정·상태·삭제·태그는 현재 정보 확인 경로를 제공한다.
- 모바일 카드/단독 상세와 PC 표/패널, 모달 포커스·Tab 순환·Esc·닫기 후 복귀를 적용했다.
- 주간 증감·추이 차트, 반납 당시 정상/손상 표시, 태그 교체/해제, 강제 반납, 권한 편집, 독촉·제재는 구현 범위에서 제외했다.

## 구현된 키오스크 공통 UI

- Windows 가로 배치와 태블릿 가로/세로 터치 배치를 제공한다. 공통 UI 구현은 설치 앱 완성을 의미하지 않는다.
- 대기·코드·종류·NFC·상태 선택·최종 확인·저장·완료 및 오류 복구를 구현했다. 반납 코드 입력만으로 저장하지 않으며 정상/손상은 최초 미선택이다.
- 키패드는 지우기·0·확인, 숫자키·Enter·뒤로가기·취소 확인·Esc를 지원한다.
- 일반 유휴 180초, 만료 전 경고 20초, 완료 후 12초 자동 복귀를 적용했다. 저장 중과 결과 불명확 상태에서는 취소·이전·자동 초기화로 요청 문맥을 지우지 않는다.
- 대여는 동일 grant·멱등키·본문, 반납은 동일 ticket·proof·상태·코드로 복구한다. 반납 API에 새 멱등 헤더를 추가하지 않았다.
- 명확한 코드 거부는 수정 가능하게 하고, 만료 인식은 재인식을 안내한다. 불명확 결과 뒤 인증/인식 만료는 실패로 단정하지 않고 관리자 확인 상태를 유지한다.
- 리더기를 한 번 구독하고 단계 외 입력·중복 스캔을 억제한다. 앱 복귀 시 연결과 만료를 재평가한다.
- 종류 API에 없는 재고 수량은 추정하지 않는다. 최종 예정일은 서버 dueAt만 표시한다.
- `platform.ts`의 `window.tagbackKioskHost` v1은 reader와 선택적 뒤로가기·운영 패널·종료 인터페이스다. Windows 기본 리더기는 기존 SSE 브리지이며 Android 네이티브 어댑터가 없으면 연결 안 됨으로 표시한다.
- 메모리 문맥 보존과 종료 경고는 강제 종료 후 복구를 보장하지 않는다. 호스트의 실제 ADMIN 인증·종료·자동 실행·업데이트는 후속 구현이다.

## 2026-11-13 패키징 설계 추가

## 2026-11-13 패키징 P1 구현

공통 kiosk 전용 빌드·호스트 연결 경계를 구현했다. `pnpm build:kiosk`로 `frontend/dist-kiosk/kiosk-app.html`과 assets, `kiosk-build.json`을 생성한다. 사용자/관리자 화면 모듈은 빌드 그래프에서 차단하고 외부 폰트 import를 웹 전용으로 분리했다. 기존 웹 진입점과 `/kiosk` 경로는 유지한다.

호스트 v2·transport v1 계약, 필수 호스트/버전 검사, 웹/host adapter, IPC 응답 상관관계·타임아웃 검사를 추가했다. 호스트 경로에서는 bearer token 대신 opaque grant handle을 사용하고 임의 URL/쿠키/헤더를 전달하지 않는다. 쓰기 재시도는 같은 operationId·본문을 유지하며 requestId만 새로 발급한다. 기존 v1 reader host는 웹에서 계속 지원한다.

상세 계약과 재현 명령은 [P1 공통 빌드·호스트 연결 계약](kiosk-host-contract.md)을 따른다. 이는 TypeScript/UI 쪽 연결 구조다. 실제 Electron/Kotlin 호스트, 프로세스 종료 후 내구성 있는 복구와 device/operation 서버 API, 실제 리더기 검증은 아직 후속 작업이다.

검증: 일반 웹 및 kiosk 빌드 통과, 단위 43개(기존 31+호스트 12), 기존 HTTP fixture 36개, 기존 kiosk fixture 17개, 전용 빌드/가상 호스트 7개 통과. 최초 browser 실행은 필요한 Playwright Chromium이 없어 실패했으며 해당 테스트 실행 파일 설치 후 검증했다. 최초 `kiosk.html`이 Vite에서 `/kiosk`와 충돌하는 문제는 `kiosk-app.html`로 수정했다. 소스 변경 중의 중간 회귀 실행은 중단하고 변경을 마친 상태에서 전체 browser 검사를 다시 통과했다.

작업은 `C:/Projects/tagback-user-web`, `codex/user-web-redesign`, HEAD `54cca26` 위 로컬 미커밋 변경이다. 새로운 exe/APK 생성·실제 DB/장치 검사·원격 fetch·커밋·푸시·병합·배포는 수행하지 않았다. 다음 구현은 P2 Windows Electron 호스트/시험 exe 골격이다.

## 2026-11-13 패키징 P2 Windows 시험 골격

`kiosk/windows`에 Electron 45.3.1 / Forge 8.0.1 호스트와 Squirrel 시험 설치 파일 구성을 구현했다. 공통 UI를 `tagback://app/`에서 읽고 manifest hash/경로를 검사한다. sandbox·contextIsolation, main-frame IPC 검사, 외부 네트워크/탐색/팝업/권한 차단을 적용했다. main이 HTTPS API 및 실제 grant를 보유하고 renderer에는 handle만 전달한다.

`PrivateBridgeMain`을 추가해 기존 PC/SC 엔진을 비공개 stdin/stdout 이벤트로 연결했다. Java 21 최소 런타임과 jar를 앱에 동봉하며 reader 프로세스 실패 시 최대 30초 backoff로 복구한다. 개발용 SSE는 유지했다. 서명 키는 PowerShell 7 CurrentUserOnly named pipe로 주입하고 Windows safeStorage 암호문으로 보관한다. GUI exe stdin 주입은 smoke에서 끝나지 않아 폐기했고, 새 방식과 실제 PowerShell 도우미를 격리 프로필·시험 키로 검증했다.

대여·반납의 메모리 기반 미확인 작업 잠금, 같은 operation/body replay, 동시 중복 호출 공유, 영수증 검증, 미확인 상태의 정상 종료 차단을 추가했다. 반납 서버 본문은 기존 계약을 유지한다. 영구 journal·장치/operation 서버 계약·ADMIN 운영은 후속 P4/P5이며 강제 종료 복구를 제공하지 않는다.

검증: 공통 kiosk 빌드, Windows package/make, 호스트 단위 8개, Java 17개, 프론트엔드 단위 43개, 설치 번들/가상 호스트 7개 통과. 최종 패키지의 모든 src 파일과 작업 폴더 원본이 일치함을 검사했다. 실제 패키지 실행에서 UI/v2 주입·Node 미노출·DevTools 차단·임의 명령/직접 네트워크 거부·미설정 이용 차단을 확인했다. 동봉 Java의 disconnected 이벤트와 EOF 종료, 실제 Windows 암호화 키 저장을 확인했다. 화면 캡처는 `kiosk/windows/out/smoke/windows-kiosk.png`.

산출물은 `kiosk/windows/out/TagBackKiosk-win32-x64/TagBackKiosk.exe` 및 `out/make/squirrel.windows/x64/TagBackKiosk-0.1.0-trial-Setup.exe`. 직접 실행은 폴더 전체가 필요하다. 실행 안내는 [Windows README](../kiosk/windows/README.md). 설치 파일은 서명하지 않은 시험 파일이며 실제 설치/제거·다른 PC·실물 NFC·서버/DB 재검증은 수행하지 않았다. P2의 타 PC 설치 인수는 미완료다. Android APK·자동 실행/업데이트·운영 잠금도 아직 후속 작업이다.

작업 위치 `C:/Projects/tagback-user-web`, 브랜치 `codex/user-web-redesign`, 기준 HEAD `54cca26`. P1/P2 작업은 로컬 미커밋 변경이며 원격 fetch/커밋/푸시/병합/운영 배포를 수행하지 않았다. 과거 P1 기록의 '실제 호스트 미구현' 상태는 이번 Windows 시험 범위에 한해 갱신한다.

## 2026-11-13 Windows 0.1.1 전체화면·스크롤 최소화

사용자가 0.1.0 설치와 정상 화면 표시를 직접 확인했다고 보고했다. 이어 기본 전체화면, 스크롤 최소화, 필수 조작 단축키를 요청해 Windows 호스트를 변경했다.
